## 선택한 범위와 연결 원칙

첫 후보는 기존 등록정보와 생성 코드의 자료 관계를 재사용해 읽기 전용 목록을 만든다. 리뷰의 안정된 폴더 ID와 아카이브의 문서 ID를 보존하고, 제목 유사도나 날짜만으로 서로 다른 자료를 자동 합치지 않는다. 기존에 명시된 한영·렉처·PDF 연결만 사용한다. 연결이 없거나 모호하면 독립 자료 또는 확인 필요 상태로 표시한다.

공개 여부는 해당 자료의 정식 공개 목록·확인한 배포 아티팩트·실제 공개 경로를 근거로 판단한다. 알림 피드에 없다는 이유만으로 미게시로 표시하지 않는다. 자료를 읽지 못했거나 공개 상태를 확인하지 못하면 `unknown`으로 표시하고 이유와 확인 시각을 둔다. 등록 상태, 후보 포함 여부, 운영에서 확인한 상태도 서로 구분한다.

처음 제공할 동작은 분류·언어·확인 상태 필터, 제목·ID·태그 검색, 기존 공개 페이지·PDF 열기, 후보가 있는 경우 해당 미리보기다. 자료를 저장·삭제·발행하거나 독자 알림을 보내는 기능은 이 후보에 포함하지 않는다. 기존 HTML·그림·수식·PDF를 변환하거나 다시 생성하지 않는다.

관리용 코드는 독자 페이지의 초기 자산에 포함하지 않는다. 첫 후보는 격리된 로컬 관리 미리보기로 검증할 수 있다. 내부 원본 경로·편집 이력·비공개 증거는 권한 있는 관리 환경에서만 다루며, 일반 공개 응답이나 독자 페이지에 노출하지 않는다. 새 인증 구성이나 유료 서비스 설정은 이번 설계에 포함하지 않는다.

## 목록 응답 계약의 개념안

아래는 추후 구현할 응답의 예시이며 운영 API가 존재한다는 뜻이 아니다. 예시의 `null`과 `unknown`은 확인하지 않은 사실을 채우지 않는 표현이다. 내부 원본 위치는 일반 공개 응답에서 제외한다.

```json
      "languages": ["ko"],

      "previewUrl": null,

```

식별자와 자료 관계가 우선이며 목록의 수량은 원본에서 계산한다. 페이지 나눔·정렬 결과는 같은 입력에서 재현 가능해야 한다. 원본 확인 실패를 빈 목록이나 정상 결과로 숨기지 않는다. 응답·경로 계약의 확정은 첫 구현에서 기존 생성기의 실제 식별자 규약과 대조한다.

## 첫 후보의 검증과 종료 조건

1. 확인한 원본 등록을 빠짐없이 읽고, 한영·PDF 사본을 논리 게시물과 구분한다. 카탈로그·아카이브 관계가 모호한 자료는 경고로 남긴다.
2. 알림 피드에 없는 아카이브 자료가 자동으로 미게시로 분류되지 않는다. 읽기 실패와 확인 불가는 명시적으로 표시한다.
3. 필터·검색·공개 링크·미리보기가 자료 ID와 실제 경로에 맞게 동작하고, 잘못된 ID·빈 결과·누락 자료를 처리한다.
4. 후보 생성 전후 기존 원본·등록정보·공개 HTML·PDF의 해시를 비교해 의도하지 않은 변경이 없음을 확인한다.
5. 읽기 전용 실행이 저장·발행·삭제·알림 요청을 만들지 않고, 관리 코드가 독자 초기 자산에 추가되지 않았음을 확인한다.
6. 권한 밖의 내부 경로·비공개 증거·개인 계정 정보가 응답·화면·로그에 노출되지 않는다.
7. 검증한 환경과 미검증 환경을 기록하고, 구현 완료·운영 배포·실사용 관찰을 별도 상태로 남긴다.
