## 선택한 범위와 연결 원칙

첫 후보는 기존 등록정보와 생성 코드의 자료 관계를 재사용해 읽기 전용 목록을 만든다. 리뷰의 안정된 폴더 ID와 아카이브의 문서 ID를 보존하고, 제목 유사도나 날짜만으로 서로 다른 자료를 자동 합치지 않는다. 기존에 명시된 한영·렉처·PDF 연결만 사용한다. 연결이 없거나 모호하면 독립 자료 또는 확인 필요 상태로 표시한다.

공개 여부는 해당 자료의 정식 공개 목록·확인한 배포 아티팩트·실제 공개 경로를 근거로 판단한다. 알림 피드에 없다는 이유만으로 미게시로 표시하지 않는다. 자료를 읽지 못했거나 공개 상태를 확인하지 못하면 `unknown`으로 표시하고 이유와 확인 시각을 둔다. 등록 상태, 후보 포함 여부, 운영에서 확인한 상태도 서로 구분한다.

처음 제공할 동작은 분류·언어·확인 상태 필터, 제목·ID·태그 검색, 기존 공개 페이지·PDF 열기, 후보가 있는 경우 해당 미리보기다. 자료를 저장·삭제·발행하거나 독자 알림을 보내는 기능은 이 후보에 포함하지 않는다. 기존 HTML·그림·수식·PDF를 변환하거나 다시 생성하지 않는다.

관리용 코드는 독자 페이지의 초기 자산에 포함하지 않는다. 첫 후보는 격리된 로컬 관리 미리보기로 검증할 수 있다. 내부 원본 경로·편집 이력·비공개 증거는 권한 있는 관리 환경에서만 다루며, 일반 공개 응답이나 독자 페이지에 노출하지 않는다. 새 인증 구성이나 유료 서비스 설정은 이번 설계에 포함하지 않는다.

## 목록 응답 계약의 개념안

아래는 추후 구현할 응답의 예시이며 운영 API가 존재한다는 뜻이 아니다. 예시의 `null`과 `unknown`은 확인하지 않은 사실을 채우지 않는 표현이다. 내부 원본 위치는 일반 공개 응답에서 제외한다.

```json
{
  "schemaVersion": 1,
  "sourceRevision": null,
  "releaseRevision": "a1189c8d6d46d1b55acd046c99a89d94a650160f",
  "checkedAt": null,
  "items": [
    {
      "id": "review:example-topic",
      "kind": "review",
      "title": "예시 제목",
      "languages": ["ko"],
      "tags": [],
      "registrationState": "registered",
      "releaseState": "unknown",
      "releaseEvidence": [],
      "publicUrls": [],
      "relatedDocumentIds": [],
      "previewUrl": null,
      "warnings": ["공개 상태 확인 전"]
    }
  ],
  "nextCursor": null
}
```

식별자와 자료 관계가 우선이며 목록의 수량은 원본에서 계산한다. 페이지 나눔·정렬 결과는 같은 입력에서 재현 가능해야 한다. 원본 확인 실패를 빈 목록이나 정상 결과로 숨기지 않는다. 응답·경로 계약의 확정은 첫 구현에서 기존 생성기의 실제 식별자 규약과 대조한다.

## 첫 후보의 검증과 종료 조건

1. 확인한 원본 등록을 빠짐없이 읽고, 한영·PDF 사본을 논리 게시물과 구분한다. 카탈로그·아카이브 관계가 모호한 자료는 경고로 남긴다.
2. 알림 피드에 없는 아카이브 자료가 자동으로 미게시로 분류되지 않는다. 읽기 실패와 확인 불가는 명시적으로 표시한다.
3. 필터·검색·공개 링크·미리보기가 자료 ID와 실제 경로에 맞게 동작하고, 잘못된 ID·빈 결과·누락 자료를 처리한다.
4. 후보 생성 전후 기존 원본·등록정보·공개 HTML·PDF의 해시를 비교해 의도하지 않은 변경이 없음을 확인한다.
5. 읽기 전용 실행이 저장·발행·삭제·알림 요청을 만들지 않고, 관리 코드가 독자 초기 자산에 추가되지 않았음을 확인한다.
6. 권한 밖의 내부 경로·비공개 증거·개인 계정 정보가 응답·화면·로그에 노출되지 않는다.
7. 검증한 환경과 미검증 환경을 기록하고, 구현 완료·운영 배포·실사용 관찰을 별도 상태로 남긴다.

### 첫 실행 경로와 권한

첫 후보는 호출자가 지정한 소스와 **이미 검증한 로컬 공개 묶음**을 읽어 새 보호 폴더에 JSON·로컬 정적 목록을 만든다. baseline의 네트워크 획득은 기존 운영 경로에서 별도로 수행한다. 목록 실행은 빌드·`prepare_publication`·`write_intent`·등록/선언 갱신·파일 import·DB·발행·알림을 호출하지 않는다. 첫 버전의 `candidateState`는 `not_provided`, `previewUrl`은 `null`로 두며 후보 미리보기 연결은 후속 범위다.

관리용 템플릿·코드는 독자 초기 자산과 공개 빌드에 넣지 않는다. 산출물은 Git/공개 배포에서 제외한 `output/` 아래 새 폴더에 두고 `.keep`를 미리 둔다. 출력 경로와 상위 구성요소의 심볼릭 링크를 거절하고 기존 폴더를 덮어쓰지 않는다. 로컬 미리보기에는 필요할 때 loopback 서버만 사용하며 외부 리소스·분석·Worker 세션을 초기화하지 않는다. 일반 공개 관리자 URL이나 인증 API를 새로 배포하지 않는다.

기존 publisher Bearer는 카탈로그 동기화·DB/queue 쓰기의 자격이며 관리 브라우저에 넣지 않는다. 개인 학습의 owner/reviewer는 개인 자료 권한이다. `study-library`의 승인 결과도 `published:false`·`editorialExportRequired`이며 이 목록의 공개 게시 인가가 아니다. 개인 초안·필기·계정·구독·기기·endpoint·원시 운영 로그는 입력에서 제외한다. 정상 게시의 기존 권한·검증은 유지한다.

### 응답과 상태의 의미

`schemaVersion:1`의 필드는 다음으로 고정한다. 허용 필드만 새 객체에 투영하고 등록 JSON 전체를 응답으로 복사하지 않는다.

| 구분 | 필드와 의미 |
| --- | --- |
| 전체 | `sourceRevision`(확인한 소스 커밋 또는 null), `sourceInputState`(선택 입력과 그 커밋의 일치/차이/미확인), `checkedAt`, `registrationSnapshotToken`, `snapshotToken`, `baseline`, `totals`, `items`, `nextCursor:null`. `totals`는 등록 원본 행·조정 행·표시 합계와 kind/series별 수를 나눠 계산한다. |
| 공개 묶음 | `baseline.status`는 `verified_deployed_artifact` 또는 명시적 `not_provided`. 확인한 `releaseRevision`, 원본 release/catalog/updates SHA, origin, 확인 시각을 연결한다. |
| 자료 | `id`, `sourceId`, `kind`, `series`, `title`, `languages`, `category`, `tags`, `originalPublishedDate`, `registrationState`, `notificationCatalogMember`, `checkedInputState`, `releaseMembership`, `contentComparison`, `candidateState`, `publicLinks`, `relatedDocumentIds`, `versionEvidence`, `previewUrl`, `warnings` |
| 등록 | `registrationState`는 `registered` 또는 `baseline_only_source_missing`이다. 후자는 실제 공개 묶음에만 있는 ID를 보존하는 조정 상태다. |
| 공개 소속 | `releaseMembership`은 `present`, `absent`, `unknown`이다. 완전한 동일 릴리스 묶음에서만 `absent`를 말할 수 있다. 알림 누락·요청 존재·소스 HEAD 차이로 판단하지 않는다. |
| 내용 비교 | `contentComparison`은 `matches`, `differs`, `unknown`, `not_applicable`와 `basis`·`coveredPaths`를 함께 둔다. 현재 입력/검토한 예상 출력/실제 공개 bytes를 구분한다. 소속 확인만으로 내용 일치를 표시하지 않는다. |
| 입력 근거 | `checkedInputState`는 article 입력과 전체 등록의 비교를 각각 `matched`, `changed`, `not_recorded`, `unknown`으로 기록한다. v2의 허브 정보 변경과 protected article 변경, v1의 불확실성을 구분한다. |
| 링크 | `publicLinks`에는 역할·언어·정규 공개 URL·알려진 SHA/size·근거 상태만 둔다. 봉인에 있는 경로와 실제로 새 HTTPS 읽기까지 확인한 경로를 구분한다. 첫 생성기의 개별 URL `httpsVerifiedAt`은 null이다. 외부 링크는 별도 `external_link_only`다. |
| 버전 | `versionEvidence`는 필요한 읽기 해시/현재 `document_version`/근거 범위만 둔다. 내부 원본 경로·본문·비공개 메모·개인 식별정보를 내보내지 않는다. 토큰은 읽은 입력을 식별하며 쓰기 인가·자동 충돌 방지의 구현이 아니다. |

`review_inputs`의 source·전체 등록·protected 등록 해시와 지속 요청 v1/v2를 비교한다. 읽기 과정에서 오래된 요청을 업그레이드하거나 갱신하지 않는다. 기존 변경 선언의 `after`는 근거가 실제로 결속된 출력 경로에 한해 사용한다. HTML의 내용 해시와 reader 장식 후 raw 아티팩트 해시는 별도다. `public_reviewed:true`, 현재 archive 버전 토큰이나 source HEAD만으로 과거 감수/예상 출력 SHA를 만들어내지 않는다. 비교할 근거가 없으면 `unknown`과 이유 코드를 남긴다. skip-ci 운영 기록 때문에 HEAD와 공개 revision이 다른 것은 미게시·장애의 근거가 아니다.

등록·묶음·정규화한 허용 행의 정렬된 해시에서 토큰을 계산한다. `checkedAt`·UI 검색 상태는 snapshot 토큰에 포함하지 않는다. 소비한 입력의 앞뒤 해시/파일 목록을 재확인하고 도중 변경은 명시적 오류로 중단한다. 관련 없는 작업 파일의 존재를 잠금이나 강제 정리의 근거로 삼지 않는다. 이 검사는 분산 잠금·완전한 원자적 소스 저장을 구현한 것이 아니다.

### 한도·실패·화면

첫 전체 목록은 최대2,000행·UTF-8 JSON 2,000,000바이트다. 로컬 화면은 기본50행·최대100행씩 표시하고 제목/ID/태그 검색은200문자로 제한한다. 기존 소스 필드 검증을 재사용하며 제목·ID·행을 조용히 자르지 않는다. 원 발행일 내림차순·관리 ID 오름차순으로 재현 가능한 순서를 만든다. 첫 후보는 전체 bounded snapshot의 로컬 페이지 나눔이며 API cursor를 구현하지 않는다.

허용 JSON 입력은 파일별5,000,000바이트·합계16,000,000바이트를 넘으면 중단한다. PDF와 원고의 해시 읽기는 별도이며 전체 bytes를 응답에 넣지 않는다. 누락 원장·중복 JSON key/ID·잘못된 형식·심볼릭 링크·권한 밖 경로·한도 초과·입력 변경은 정상 빈 목록으로 숨기지 않고 reason code로 실패한다. 기존 archive/external reader의 초기화용 원장 누락→빈 목록 동작 앞에 이 저장소의 필수 archive manifest/entries·외부자료 원장 존재와 입력 크기 검사를 둔다. 제공한 baseline이 손상·불일치하면 거절하고, 호출자가 baseline을 명시적으로 생략했을 때만 공개 상태를 `unknown`으로 둔다. 실패한 실행은 이전 정상 산출물을 덮어쓰지 않는다.

화면은 분류/series/언어/근거 상태 필터, 제목·ID·태그 검색, 기존 검증된 공개 링크 열기를 제공한다. 문자열은 안전한 JSON escaping과 text DOM으로 출력하고 `innerHTML`·이벤트 속성으로 해석하지 않는다. 사이트 링크는 허용된 HTTPS origin·scope와 명시된 경로만, 외부 자료는 기존 검증된 HTTPS landing page만 사용한다. 임의 로컬 파일·credential URL·실행 스킴·query가 담긴 비공개 링크를 열지 않는다. 로컬 키보드·320px 화면과 긴 제목/빈 결과/오류 상태를 검토한다.
