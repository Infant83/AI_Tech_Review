## 판단과 적용

사용자가 공유한 AI 개발의 shadow IT 우려를 읽고 ADOPT 내부 보안·안정성 파트(SRU)를 구성했다. 자산·담당·접근 경계·비밀정보·의존성·에이전트 도구 경계·안정성·복구를 담당한다. 조직도·운영 기준·공용 인계와 자산 7개 기록을 연결했다. 내용 판단과 일반 게시 권한은 편집부(AEDAUT)에 유지한다.

기존 ADOPT 예약의 프롬프트에 SRU를 통합했다. 설정을 다시 읽어 프롬프트와 갱신 시각만 바뀌고 기존 식별자·이름·대상 대화·활성 상태·새벽 3시 주기가 보존됨을 확인했다. 별도 상주 프로세스나 예약을 추가하지 않았다.

GitHub API로 기존 secret scanning과 push protection을 활성화하고 재조회했다. 추가 승인 게이트나 credential 범위 확대는 수행하지 않았다. 탐지 후보는 별도 일감에서 분류하며 현재 9개 모두 유효성 미확인이다. 만료된 서명 URL의 키 식별자 문맥에서는 비밀 키 필드가 함께 확인되지 않았다. 다른 후보를 파일 형식만으로 오탐 처리하지 않았다.

게시 기능이 참조하지 않는 과거 원시 네트워크 기록은 실제 파일을 로컬에 보존하고 Git 추적에서 제외하며 정확한 경로를 ignore했다. 과거 이력 삭제·키 검증·폐기·탐지 경고 종료는 수행하지 않았다. 민감한 값·상세 위치·원시 기록은 이 실행 문서에 포함하지 않는다.

## 검증

독립 검증자가 기존 backend를 로컬 Miniflare와 생성된 테스트 자료로 검사했다. Node 22.14.0에서 잠금 파일 설치·구문 검사와 테스트 56개가 통과했다(실패·건너뜀 0). 운영 자격증명·운영 DB·실제 메일·푸시를 사용하지 않았다. 소스·잠금 파일을 바꾸지 않고 같은 명령을 기존 Pages CI의 build에 추가했다.

독립 검토에서 SRU의 내부 편제·권한·사람 감수·민감 증거·정기 운영의 표현과 비 main 분기의 배포 제외 조건을 확인했다. 문서 링크·JSON·diff 형식 검사, Mermaid 실제 브라우저 렌더링을 확인했다. 실제 GitHub Ubuntu CI 실행과 main 통합은 아래 후속 결과에 연결한다.

익명 HTTPS GET에서 홈·PDF 리더·공개 설정은 200, 익명 상태는 계정 없음, 개인 노트 목록은 401을 확인했다. 이는 운영 계정 간 전체 권한·공급자 설정·개인 DB 복원의 감사를 완료한 것이 아니다. CSP 헤더 미관측은 즉시 취약점으로 단정하지 않고 reader·worker·폰트·수식의 호환성 조사 대상으로 남긴다. Dependabot 경고는 비활성/접근 불가, code scanning은 분석 미관측으로 남기며 권한을 확장하지 않았다.

## 통합·배포와 복구

이번 변경은 조직·CI·Git 위생과 공급자 보호 설정이다. 공개 페이지·게시물·런타임 인증·DB 스키마·편집부 예약은 바꾸지 않는다. 별도 브랜치의 기존 workflow_dispatch로 검증하고 Pages 배포·복구 사본·독자 동기화를 실행하지 않는다. 일반 Actions 검증 artifact와 공개 HTTPS 기준선 읽기는 수행한다. 브랜치 검증은 기존 concurrency 그룹을 사용하므로 main 작업을 잠시 대기시킬 수 있다.

실제 롤백·운영 데이터 복원은 실행하지 않았다. 정적 복구 사본을 개인 D1 백업으로 간주하지 않는다. 공개 소스의 CI·문서 변경은 이전 커밋의 해당 경로로 복구할 수 있고 GitHub 보호 설정은 별도로 관리한다.

## 다음 작업

실제 CI 결과를 확인해 통합 근거를 남긴다. SRU는 다음 새벽 회차에서 탐지 후보 분류와 자산의 미확인 항목을 우선 검토한다. 실제 유출·노출이 확인되면 영향에 맞게 우선순위를 높인다. 손상된 기존 PDF와 관리 도구 등 다른 열린 운영 일감은 기존 상태를 유지하며 보안팀 신설만으로 해결 처리하지 않는다.
