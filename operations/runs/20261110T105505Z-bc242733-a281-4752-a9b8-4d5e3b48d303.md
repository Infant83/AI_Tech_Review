## 읽기 점검과 독립 검토

- [최근 CI](https://github.com/Infant83/AI_Tech_Review/actions/runs/42794409298)의 네 작업이 성공했고 실제 공개 릴리스와 서버 카탈로그의revision이일치한다. 공개 `/v1/config`는 `pushEnabled:true`다.
- 기존 GitHub 연결과 Cloudflare OAuth를 지원 CLI(wrangler4.159.0)의 whoami로 재확인했다. 지원 CLI의 `whoami` 이후 D1에 SELECT 집계만 수행했다. 구독endpoint·암호키·기기ID·쿠키·원문로그는조회출력하거나공개기록에넣지않았다.
- 후보 새 글 `2026-11-09_atrl-agentic-atelier`의 발행 이벤트는 11/10 08:55:15 UTC에 생성됐다. fanout이완료됐고대상배송은모두첫시도HTTP201·sent다. pending/retry/sending/dead/suppressed/failed는0이다.
- 최근7일의article이벤트11건·배송26건을집계했으며모두HTTP201·sent·첫시도다. 이는제공자수락의집계이며실제단말표시나사용자의해당기기식별은아니다.
- 독립 백엔드 담당은 새ID만발행이벤트를만드는기존정책과배송처리를확인했다. 같은ID의본문개정·재배포는새글푸시대상이아니다.
- 독립 프런트엔드 담당은 공개sw.js·reader-engagement.js·reader-updates.js와현재원본의정확한일치를확인했다. 로컬배지회귀20개통과;실제알림전송은없다.

## 아직 구분해야 할 단계

앱 아이콘 숫자는 현재SW의push수신후증가한다. 그러나 `showNotification()`과배지기록이독립실행되므로배지는알림표시성공의증거가아니다. 기존최근수신목록도push수신을뜻하며OS표시결과를수집하지않는다. 사이트내업데이트숫자라면다른경로일수있다.

사용자가해당앱의알림설정에서문제글의최근수신제목·시각을확인하면SW수신이후표시단계와그이전단계를나눌수있다. 실제 iPhone·모바일 브라우저·OS 설정을이번조사에서확인한것으로표시하지않는다. 재설치·구독해제·데이터삭제를먼저권하지않는다.

## 작은 진단 보완과 인계

기존 CI는 서버가 반환한 새 글 수·큐 접수 수·기준선/재처리 여부를 버리고 목록 동기화 수만 출력했다. `sync_publications()`가 허용한 비민감 필드 `newArticles`, `queuedEvents`, `baseline`, `replay`만 타입 검사 후 보존하도록 수정했다. 누락·잘못된 타입을 0/false로 바꾸지 않고 원문 응답·구독·키도 출력하지 않는다. 알림 정책·발송·서버 상태는 바꾸지 않는다.

관련 Python 회귀 41개가 통과했다. 정상 0/false 보존, 누락·타입 오류 생략, 민감 필드 차단 검증을 추가했다. 독립 감수와 JSON·링크·diff 검사도 통과했다. 이 변경은 다음 정상 게시의 CI 진단 출력에 적용하며 실제 다음 로그는 관찰 전이다. 공개 사이트 재배포나 과거 푸시 재발송으로 검증하지 않는다.

단말증거가없어일감은needs_evidence로유지한다. 테스트푸시·과거재발송·구독/권한/키/DB쓰기·사이트재배포·실제롤백을수행하지않았다. 다음연결은사용자기기·문제글·표시위치와최근수신목록확인이다.
