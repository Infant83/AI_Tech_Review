## 별도 배포·원격 복구 계약

현재 가능한 범위는 검증된 공개 PDF의 SHA 객체/원래 URL 별칭 내보내기, Worker 매핑 결속과 GET/HEAD/Range 전달이다. 기대 SHA를 URL 요청에 고정하는 동작과 원격 자산의 봉인/복구 지원은 구현되지 않았다. 개별 Worker 코드 버전에 결속된 매핑과 GitHub Pages의 카탈로그 배포는 서로 다른 서비스이므로, 업로드 후 매핑·카탈로그를 순서대로 배포하는 것만으로 판본 정합성이 끝나지 않는다. 새 SHA로 별칭을 먼저 바꾸면 구 카탈로그가 기대한 SHA와 어긋날 수 있는 준비 설계 조건이며 현재 운영 장애의 발견은 아니다.

[사이트 운영 지침](../../SITE_OPERATIONS.md)에 활성화 전 기대 SHA/revision 고정 요청 또는 구·신 판본 공존, 구 카탈로그/신 전달 코드·신 카탈로그/구 전달 코드·서비스별 되돌림 시험을 명시했다. 원격 key/URL·SHA·크기·매핑 판본을 release·연속성·복구에 결속하고 업로드 전체 bytes 검증을 게시보다 먼저 끝내야 한다. 현재 capture/seal/recovery는 로컬 PDF를 요구하므로 누락 파일 검사를 완화하지 않고 원격 검증/복원을 갖춘 뒤 정적 사본을 제거한다. 기존 공개 URL·문서 ID·구판/필기·알림 연결을 유지하고 공개 PDF 저장소를 개인 문서/필기와 섞지 않는다. [R2 binding](https://developers.cloudflare.com/r2/get-started/workers-api/), [권한 범위](https://developers.cloudflare.com/r2/api/tokens/)
