# 사용자 직접 요청 · 조회 지표와 Google 검색 발견

운영팀(ADOPT)은 사용자의 조회 지표 확인·Google 검색 노출 개선 요청을 [검색 발견 일감](../issues/OPS-0261423d-909a-4fb1-a33a-b0517c77d578.json)으로 연결했다. 편집부(AEDAUT)의 과학 본문·제목·요약·콘텐츠 예약과 일반 게시 권한은 유지했다.

공개 집계 GET을 읽고 수집 코드와 대조했다. 현재 수치는 브라우저ID 누적/한국시간 오늘과 브라우저ID·글ID·한국날짜별 하루 한 번 열람이다. 사람 수·전체 pageview·순수 외부 방문자로 바꾸어 보고할 수 없으며 소유자 방문 제외 근거도 없다. 직접 PDF 열람이나 모든 페이지 이동을 포괄하지 않는다. 수집 POST·원시 visitor/IP/cookie·DB 읽기/변경은 없고 사용자용 수치와 원시 응답은 공용 기록에 복제하지 않았다. 최종 집계 읽기는11/28 20:55 KST에 마쳤다. 기존 Cloudflare CLI 인증은 유효하나 analytics scope는 없었고, 브라우저는 암호 입력이 필요했다. 새 추적식별자·과금·권한 확대는 만들지 않았다.

독립 SEO 조사에서 공개 HTML6표본의200·self-canonical·한영 hreflang·정적 링크와301을 확인했고 관찰한 meta/header noindex 차단은 없었다. root/subpath sitemap은404였으며 기존 생성 경로가 없었다. host root robots의 Cloudflare 주석은 차단 근거가 아니며 이 저장소의 subpath 배포로 host root robots 설정을 완료했다고 주장하지 않는다.

등록된 공개 HTML과 실제 canonical만 수집하는 sitemap을 구현했다. KO/EN·목록2페이지 이후를 보존하고 noindex/refresh·비등록/비공개·PDF·symlink를 제외한다. 근거 없는 lastmod는 만들지 않는다. Google이 소유권 화면에서 실제 제공한 공개 HTML 확인파일은53B와 SHA를 고정하고, 정확한 한 파일만 설치·검증·허용한다. 일반XML/google*.html 허용을 넓히지 않았다. 확인파일을 reader 보강과 갱신 페이지 목록에서 제외하고 설치·재보강 뒤에도 bytes를 검증한다. 초기 후보에서 갱신 목록에 확인파일이 포함되는 결함을 수정했으며 운영 장애는 아니었다.

최종 관련81검사(1.690초)와 독립 정적 감수를 통과했다. 최초88b5f055/d62915ca 후보와 자기 기록·다른 작업의 미완성 변경을 보존하고, 최신 cc977a92/정상 T-gate98be79e8 게시를 인수한 e93522b7 후보로 재구성했다. 수정 범위는 sitemap helper/검사, 기존 publish·enrich·release 경계, 정확한 Google 확인파일/안내와 운영 문서다. 원문·ID/URL·한영 연결·PDF는 수정하지 않았다.

로컬 무거운 구간 종료와 다른 편집 작업의 active 상태를 확인해 큰 검사/빌드를 중첩하지 않았다. 처음에는 다음11/29 05:30에 기술 검증·배포를 잇고 V 미래 caller 검토를13:30으로 잠정 재배정했다. 이후 기존 workflow_dispatch의 non-main 경로가 서버에서 독립 후보를 만들고 main 배포·복구·알림은 건너뛰는 지원 경로임을 확인했다. 새 예약·상주 감시·자동잠금 없이 현재 사용자 작업을 이어갔다.

별도 후보 [46141234578](https://github.com/Infant83/AI_Tech_Review/actions/runs/46141234578)은 전체 build·prepare·연속성·예산·봉인 검증에 성공했고 배포/복구/알림은 예상대로 skip했다. 최신 main과 다른 게시 진행 상태를 다시 확인한 뒤8c962d2c9e75f91feefe47c39e0a0298f32b30ff를 기존 단일 경로로 배포했다. 실제 [46141758029](https://github.com/Infant83/AI_Tech_Review/actions/runs/46141758029)의 build·deploy·notify-readers·recovery-copy 네 작업은 모두 성공했다. recovery-copy 성공은 실제 롤백·복원 시험·개인 DB 복구와 구분한다.

12:02:41Z 실제 HTTPS 검증에서 sitemap308주소/29484B와 고정 Google 확인파일53B가 원본 및 완전 봉인 artifact_files 해시와 일치했다. sitemap SHA256은 `2e824fb3ee7516edae4f05f96db8822c735c05d671b3dfefe22683a82b3481cc`, 확인파일 SHA256은 `0a1d44f6260fee4b1e85051d9ce588f5e39c71a173792f309ee75077b3694d23`이다. 모든 sitemap target이 완전 공개 manifest에 있고 확인파일은 sitemap에서 제외됐다. 공개2920파일/974564843B·339PDF이며 기존338PDF metadata와 모든 기존 공개 경로를 보존했다. 최근 정상 T-gate 게시의99카탈로그/203아카이브 문서도 인수했다. 콘텐츠 보존 snapshot.files와 완전 artifact_files는 서로 다른 범위이며 루트 기술파일과 총량은 후자로 대조했다. 로컬 전체 build·PDF/전체 아티팩트 재다운로드는 하지 않았다.

Google의 기존 로그인과 URL-prefix 소유권 화면은 재사용했다. 최초 등록버튼의 일시적 도구중단은 해소되어 이전 수동 클릭 요청은 철회했다. 현재 계정에 이 URL-prefix의 신규 verified-owner 권한을 연결하는 VERIFY는 브라우저 도구의 새 보안민감 접근권한 실행시 확인 정책에 따라1회 확인을 요청했다. 일반 SEO/배포 운영 승인이나 일반 게시의 추가 승인자가 아니다. 사용자 응답 전에는 VERIFY·사이트맵 제출·실제 색인을 완료로 표시하지 않는다. 무응답을 승인으로 취급하지 않으며 같은 질문을 정기 회차마다 반복하지 않는다.

기술 배포를 현재 작업에서 마쳤으므로 V의 c7 완료 근거·독립5군·710/CLI5를 보존한 미래 caller 검토를 원래11/29 05:30·순번1로 복원했다. 외부 저장소 근거/장기 재평가11/29 13:30·관찰 묶음11/30 18:30·다음 주간12/4 13:30은 유지한다. 다음 회차는 새 공개/오류·사용자 응답만 확인하고 정상 배포·같은 검사·발행을 반복하지 않는다. 사용자 확인을 받으면 준비된 Google VERIFY→사이트맵 제출→필요 소수 URL검사를 잇되 실제 Google 색인/노출은 별도 관찰한다.

최종 독립 기록 감수는 기술 배포와 Google 실행 확인 대기, 공개 수치/보존, V 일정 복원 및 기존 관찰·비공개 경계의 일관성을 PASS로 인수했다. 같은 전체 build나 정상 배포를 다시 실행하지 않았다.
