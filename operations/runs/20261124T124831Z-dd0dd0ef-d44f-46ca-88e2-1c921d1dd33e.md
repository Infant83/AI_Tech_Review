## 다음 실제 강의에서의 HTTP 캐시 검증

기존 카탈로그 수정 `934a9076ffb07b05cfa9f3fc2a71dd9bbe66c4e4` 이후 처음 자연스럽게 수신한 L015를 발행했다. 실제 HTTPS를 읽는 격리 Chromium headless-shell 159.0.8154.6에서 카탈로그는 14회차를 담은 상태로 HTTP 캐시에 남아 있었다. `Cache-Control: max-age=600`, 기준 응답 Date 12:36:20 UTC와 조회 시각 12:42:25 UTC의 차이는 약365초였다. cache-only 응답은 전송0으로 이전 카탈로그를 반환했다.

캐시나 개인 저장소를 지우거나 응답을 가로채지 않고 L015 필기 주소로 이동했다. 리더가 이전 카탈로그를 읽은 뒤 자동 재검증으로 새 카탈로그를 받아 16쪽 L015를 열었다. PDF 바이트·fingerprint는 검수판과 일치했다. 실제 UI에서 2쪽 이동·일반 다시 열기 뒤의 빈 필기·북마크·읽기 위치가 같았고, 기존 L014로 돌아가도 PDF와 2쪽 위치가 유지됐다. 실제 HTTPS의 회차 등록부·한영 주소·PDF 해시도 독립 대조했다.

원래 결함과 503/no-store 때의 메모리 보존·비어 있지 않은 마우스 필기·명시적 선택 경합은 기존 수정 기록의 범위를 유지한다. 이번 실행에서 실제503을 재발시키거나 기존 사용자의 계정·필기를 시험한 것은 아니다. 물리 iPad/Pencil 및 실시간 협업 검증도 아니다. 새 원인이나 공통 코드를 추가하지 않고, 다음 자연 발행에서 확인하기로 한 관찰 조건을 충족해 카탈로그 일감을 종료한다. 기존 강의 수신 확인은 계속하며 의미 있는 재발은 같은 일감에 연결한다.

## 복구 사본은 생성됐고 자동 삭제는 보류됨

CI는 현재 발행본의 복구 사본 `14920743068`을 업로드했다. 완료 뒤 별도 조회에서 미만료·소스/run 일치와 크기765,254,905B, digest `sha256:c853eba57abaa9efdf9498ae8a9de28fbecda51948434e6a1fe8483fabc511e6`을 확인했다. 업로드·CI 내부 검증과 별도의 전체 다운로드/재해시·실제 복원은 구별한다. 후자는 수행하지 않았다.

같은 정상 CI의 보존 단계는 `incomplete_metadata`로 삭제를 거절했다. 원시 요약의 `status=refused`, `apply_requested=true`, `deleted=[]`, `delete_attempted=[]`, `unconfirmed_delete=[]`를 확인했다. 이 단계의 성공 종료를 최신3개로 실제 정리됐다는 뜻으로 해석하지 않는다. 확인된 새 복구 사본과 공개 PDF를 보존하며 수동 삭제·추가 권한·반복 실행은 하지 않았다. 페이지 공개와 복구 사본 생성의 실패는 관측되지 않았다. 소스의 보존 함수는 거절 때 반환값1을 만들지만 CLI 진입점이 `main()`의 반환값을 종료 상태로 전달하지 않는 것을 확인했다. 따라서 녹색 job은 이 삭제 거절을 드러내지 못했다. 이는 metadata가 불완전했던 공급자 쪽 원인을 확정한 것과 구별하며, 이번 강의 발행에서 공통 코드나 검사 기준을 바꾸지 않았다.

이 관찰은 기존 파일·복구 관리 일감에 독립 이벤트로 인계한다. ADOPT의 다음 기존 회차에서 완전한 metadata가 조회되는지와 현재 사본 보존 조건을 확인한다. 이번 발행을 이유로 기존 일정·등급·외부 저장소 권한·집필·메일 예약을 바꾸지 않는다.

## 브라우저 검수 범위

후보의 한영 모바일 목록·요약·작은 링크·PDF 리더는 실제 Chromium의 정확한 후보 파일 HTTPS fixture로 확인했다. 실제 HTTPS의 카탈로그·리더 캐시 시험은 응답 가로채기·캐시 초기화가 없는 별도 브라우저였다. macOS headless의 일부 허브 실행에서 renderer 종료가 발생했고 service worker를 막은 별도 시험 문맥에서는 허브가 열렸다. 이는 검수 환경의 분리 관찰이며 서비스 워커 소스 결함이나 실제 사용자 장애의 원인을 확정한 기록이 아니다. 공개 서비스 워커·권한·보안 설정은 수정하지 않았다. QA 화면과 원시 증거는 공개 Git과 배포물에서 제외한다.
