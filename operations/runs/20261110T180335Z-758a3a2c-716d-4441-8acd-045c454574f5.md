## 이번 실행의 판단

사용자가 테스트 알림을 누른 시점에 이전 글도 함께 표시됐다고 한 [푸시 지연 일감](../issues/OPS-5b6bb0ae-576f-46db-8a38-91255c5e3dba.json)을 이어갔다. 기존 조사에서 테스트 요청의 과거 글 재발송 경로는 없었고, 같은 구독의 후보 글은 테스트 전에 이미 제공자 HTTP201 수락·첫 시도 상태였다. 단말 도착·OS 표시 시각은 확인하지 못했다.

이번 주요 작업은 기존 opt-in 알림이 제공자에 즉시 전달 시도를 요청하도록 전송 우선순위를 조정하는 것이다. 원래 지연의 원인을 확정한 수정으로 취급하지 않는다. PDF 연속 스크롤·도구별 링크, 독자 통계 기획, 손상 PDF 원본 조사는 기존 일감에 남기며 병행 구현하지 않았다.

## 검사와 실제 배포

`npm run check`와 격리 `npm test` 57개가 통과했다. high·TTL·Topic, 독립 복호화와 VAPID 서명 검사를 유지했다. 추가 통합 검사는 사용자 요청 테스트가 요청자 한 명의 배송만 만들고 이미 완료한 글을 다시 보내지 않는지 확인한다. 최초 추가 검사에서 테스트 fixture의 큐 관측 경로가 실제 호출 경로와 달라 실패했고, 같은 격리 binding을 사용하도록 고친 뒤 전체 57개를 통과했다. 외부 푸시 요청은 발생하지 않았다.

기존 Cloudflare OAuth와 지원 CLI `wrangler 4.159.0`을 재확인했다. 배포 전 활성 버전·기존 D1/큐/비밀값 binding 메타데이터·호환 설정을 대조했다. 비밀값 자체는 읽거나 출력하지 않았다. dry-run 통과 후 `--keep-vars --strict --autoconfig=false`로 기존 Worker에 배포했고, 소스 태그 `adopt-push-ac43e5109b20`와 새 버전의 활성 100%를 재조회했다. 새 자원·권한·키·마이그레이션을 만들지 않았다.

독립 담당도 전후 배포 메타데이터·집계를 대조하고 실제 HTTPS 설정200·익명 계정200/null·노트401 및 정적 revision 유지를 재조회했다. 공용 기록의 개인정보·상태·검증 범위 감수도 통과했다. 배포 후 읽기 확인 결과는 다음과 같다.

- [공개 설정](https://api.infant83.io/v1/config)은 HTTPS200, `pushEnabled:true`이며 기존 공개 VAPID 키가 동일하다.
- 익명 `/v1/study/me`는 200·`account:null`, 익명 `/v1/study/notebooks`는 401이다. 최초 `/v1/study/session` 401 검사는 구현된 세션 경로를 잘못 가정한 점검이었다. 소스 계약을 확인해 올바른 `/me`로 다시 검사했다.
- 배포 전후 binding 메타데이터·runtime 설정과 D1의 구독·이벤트·배송 상태 집계가 동일하다. 기존 자료를 변경하는 요청은 하지 않았다.
- [정적 릴리스](https://infant83.io/AI_Tech_Review/publication-release.json)는 HTTPS200·`50fb320`으로 유지된다. 이번 커밋은 `[skip ci]`로 정적 Pages 배포를 유발하지 않았다.

`high`는 제공자에 즉시 전달 시도를 요청하며 기기의 집중 모드나 표시 정책을 우회하지 않는다. [Apple Web Push 안내](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)와 [RFC8030 우선순위 규정](https://www.rfc-editor.org/rfc/rfc8030#section-5.3)을 근거로 적용했다. 서버 수락은 단말 수신·표시를 보증하지 않는다. 이번에는 새 게시·테스트 푸시·과거 재발송을 하지 않았으므로 실제 휴대폰 지연 개선은 검증 전이다.

## 메일·CI와 기존 공개 대기

연결된 메일에서 11월8일 이후 GitHub 저장소 알림을 읽기 전용으로 검색·열람했다. 직전 성공 시각에 48시간을 겹쳤으며 읽지 않음 조건 없이 6통·공개 run4개를 대조했고 추가 페이지는 없었다. 메일 성공 확인은 `2026-11-10T18:05:34.857Z`, Actions 대조 완료는 `2026-11-10T18:07:41.051Z`다. 같은 기간 30개 run의 최종 상태는 성공25·실패4·취소1, 진행 중 실행은0이다. 전체 attempt 개수는 이번 집계로 주장하지 않는다.

최초 Qunova 발행의 [42818327217](https://github.com/Infant83/AI_Tech_Review/actions/runs/42818327217) 실패 attempt들은 후손 [42824084381](https://github.com/Infant83/AI_Tech_Review/actions/runs/42824084381)의 build·deploy·recovery-copy·notify-readers 성공과 연결됐다. 반면 제목 개정의 [42828205239](https://github.com/Infant83/AI_Tech_Review/actions/runs/42828205239)와 이미 시행한 단 한 번의 재시도 [42830866020](https://github.com/Infant83/AI_Tech_Review/actions/runs/42830866020)는 Pages `syncing_files` 600초 대기 후 실패했다. 저장소의 새 제목은 아직 공개되지 않았으며 기존 판본의 한영 본문은 HTTPS200으로 열렸다.

이는 [기존 Pages 지연 일감](../issues/OPS-74bdd550-f5db-4d1d-af99-1fe4bbf48ed3.json)에 기록된 동일 상태다. 새 읽기 장애나 새 미해결 사례를 추가로 발견하지 못했고 무조건 재실행하지 않았다. 미만료 artifact의 크기 차이나 GitHub 상태 페이지의 operational 표시만으로 원인·해결을 단정하지 않는다. 메일·API 체크포인트는 [기존 정기 대조 일감](../issues/OPS-e700c2f8-42ac-4223-a572-ec8a0bc29867.json)에 갱신했다. 원문 메일·개인 정보·메시지 ID·원시 로그는 공개 기록에 넣지 않았다.

## 운영 주기·프로시커·정리

[하루 세 번 운영 일감](../issues/OPS-93fa34ff-ea74-48e8-b3d7-eeabf741d589.json)의 첫03시 기동을 실제 trigger로 확인했다. 한국시간03:03:35.419로 예정03시보다215.419초 늦었다. 기존 예약은 ACTIVE·한국시간03:00·11:00·19:00으로 저장돼 있고 설정 변경은 하지 않았다. 11시·19시의 첫 기동은 아직 관찰 전이다. AGENTS에 남아 있던 하루 한 번 표현 한 곳만 현재 세 시각에 맞췄다. 정각 실행이나 미래 가용성을 보장한 것으로 기록하지 않는다.

보안파트 프로시커의 공급자 읽기 점검에서 기존 비밀정보 탐지 후보 수는 열린6·해결3으로 변하지 않았다. 값을 열람·출력하거나 단순 후보를 유출·오탐으로 판정하지 않았다. 의존성 알림 API는 기능 비활성화로 403을 반환해 해당 공급자 점검은 미확인이다. 이번 배포는 기존 자산·권한·자료 경계를 유지했으며 전체 보안 이력을 다시 검사하거나 새 서비스를 활성화하지 않았다.

로컬 후보 보존 도구의 dry-run은 최신2개·최소7일·보호 표시를 유지했고 삭제 예정0B·실제 삭제0B·오류0이었다. 미등록·연결된 디렉터리와 진행 자료는 유지했다. 오래됐다는 이유만으로 자료·공개 PDF·원본을 삭제하지 않았다.

## 복구와 다음 인계

실제 롤백은 하지 않았다. 회귀가 확인되면 기존 Worker의 직전 버전으로 코드만 복구한다. 개인 DB 복원·정적 공개본 롤백·구독/키 초기화·이미 수락된 배송 재처리는 별개이며 이번 변경에 필요하지 않다.

- 운영팀(ADOPT)은 다음 정상 신규 발행 또는 사용자가 직접 요청한 테스트에서 제공자 수락·기기 최근 수신·실제 표시를 구분해 관찰한다. 단말 증거 전까지 푸시 지연 일감은 `in_progress`다.
- 11시·19시 회차는 새 변경과 우선 일감을 이어가며 실제 각 시간대의 첫 기동을 같은 예약 일감에 연결한다. 완료한 주간·월간 점검을 회차마다 반복하지 않는다.
- Pages 제목 개정 대기는 기존 일감에서 공급자 근거와 변경 조건을 더 확보한다. 같은 입력을 계속 재실행하거나 추가 알림을 보내지 않는다.
- 편집부(AEDAUT)의 콘텐츠 일정·발행 판단·본문·PDF 판본은 이번에 변경하지 않았다. 이번 기술 조정에 새 과금·권한 확대·사람의 추가 결정은 필요하지 않았다.
