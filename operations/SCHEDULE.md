# 운영팀(ADOPT) 과제 일정표

에이전틱 개발운영팀(Agentic DevOps Team, ADOPT)의 현재 운영 주기와 과제별 예정 시각을 이 문서에서 관리한다. 원인은 일감, 실제 실행·검증·배포는 기존 실행 기록에 남긴다. 일정표를 완료 증거나 자동 잠금으로 사용하지 않는다. 모든 시각은 **한국시간 Asia/Seoul(+09:00)**이다.

## 현재 운영 주기

- 기존 `ai-tech-review` 예약 하나를 사용한다. 기본은 매일 **03·11·19시**다.
- **2026-11-12~11-18 임시 증편:** 매일 **03·07·11·15·19시**, 하루5회. 낮에는4시간 간격이고19→03시는8시간이다.
- **2026-11-19 첫 이용 가능한 회차:** 적체·재발·실행 지연·기록 부담을 재평가한다. 이후 사용자의 연장 지시가 없으면 같은 예약을 기본3회로 복귀시키고 이 표·예약 지침을 함께 갱신한다. 별도 복귀 예약은 만들지 않는다. 실행 호스트가 이용 불가하면 복귀 역시 실제 다음 실행 때 처리하고 늦어진 사실을 남긴다.
- 11/12 03시 실행은 기존 기록을 재사용한다. 07시는 증편 설정 이전에 경과했으므로 소급 실행·누락 완료로 기록하지 않는다. **변경 후 첫 예정 회차는11/12 11시**이며 실제 기동은 별도로 확인한다.
- 회차는 재개 기회다. 다섯 시각마다 새 과제·전체 검사·배포를 만들지 않는다. 새 자료 없는 정상 점검은 조용히 기록하고 완료·실패·중대한 변화·필요한 결정만 알린다.

## 충돌·회귀·일정 지연 관리

1. **제품 구현은 한 과제씩**, 읽기 조사·서로 다른 입력의 독립 검증은 병렬로 진행한다. 같은 파일은 소유자를 정해 한 작업자가 수정한다. 각 회차는 직전 실행·실제 진행 파일·원격 main·공개 판본을 먼저 확인한다.
2. 진행 중 작업은 일감 ID·현재 단계·수정 파일 범위·기준 커밋·브랜치/작업 사본·재개 지점·다음 예정 시각을 기존 실행 기록에 남긴다. 날짜나 오래된 상태만 보고 다른 작업의 파일·잠금을 없애지 않는다. 이 표 자체가 분산 잠금은 아니다.
3. **통합·배포는 기존 단일 경로 하나**다. 오래된 site 전체를 덮지 않고 최신 동시 게시물과 검수 입력을 보존한다. 후보의 ID·URL·PDF/필기 연결·정확한 전후 해시·영향 범위 회귀를 확인하고 기존 CI의 직렬화·stale revision 차단·복구 사본·공개 HTTPS 확인을 사용한다. 일반 게시에 새 승인자를 추가하지 않는다.
4. 검사 미완료·회귀·공개 영향이 남으면 그 후보를 배포하지 않는다. 선행 과제를 이어가며 후속 제품 구현의 날짜를 조정한다. 편집 판단·실기기 근거·접근권한이 없어 막힌 항목은 이유·필요 근거·다음 검토일을 기록하고 독립 가능한 과제로 이동한다.
5. 예정일 변경은 이 표와 해당 일감의 schedule 필드를 같은 변경에서 갱신한다. 예정/실제 착수/검증/배포/관찰을 구분하고, 누락 회차는 마지막 성공 이후 새 기록을 한 번에 확인한다. 지나간 회차를 수행한 것으로 만들지 않는다.
6. 중대한 장애·노출·손실은 예정표보다 우선한다. 원인·수정·복구는 기존 정책과 일감/사고 기록에 연결한다. 편집부(AEDAUT)의 콘텐츠 일정·주제·일반 발행 권한은 이 표가 인수하지 않는다.
