# AI_Tech_Review Editorial Reference Pool

이 문서는 `AI_Tech_Review` 글쓰기와 시각 자료에서 참고할 수 있는 외부 사례를 모읍니다. 각 자료의 장점을 이번 주제·장르·저자 의도·독자와 논거에 비추어 선택합니다. 매체의 형식이나 조언을 완성 글의 공통 양식으로 고정하지 않습니다.

표지 제작에는 [과학 표지 제작 원칙](../COVER_ART_DIRECTION.md)과 [기획 양식](../templates/cover-art-brief.md)을 적용합니다. 이 문서의 참고 매체는 발상의 재료이며, 과학 분야·표현 유형·매체 선택과 검수 기준은 해당 가이드에서 관리합니다. HORIZON·Quanta의 개별 표지 사례와 제작 설명의 해석 범위도 그곳에 기록합니다.

## 과학적 논증과 주장 강도 참고 · 2026-10-26

- 사용자 지정 링크: https://lnkd.in/p/g-w2mgp4
- 확인한 원문: 위 표의 LinkedIn canonical URL. 계정 `taewi-kim`의 공개 게시물이며, 첫 문장은 “AI가 작성한 논문에는 반드시 등장하는 문장 패턴이 있습니다.”입니다.
- 확인일·범위: 2026-10-26, 공개 HTML의 게시물 설명에 실린 여섯 항목 전체를 확인했습니다. 게시글이 언급하는 별도 논문 작성 가이드 전문은 확인하지 않았습니다. 게시일은 추정하지 않습니다. 원문 전체를 저장소에 복제하지 않습니다.
- 채택한 보완: 결과의 변경 이력과 실제 실행 여부를 확인하고 중심 주장과 근거·대안 설명·성립 조건의 관계를 검토합니다. 새로움과 비교 우위, 예측과 인과를 구분하며 피규어가 논증에 필요한 비교를 보여주는지 봅니다. 직접 서술이나 예상 반박·양보가 이번 글에서 수행하는 역할을 판단합니다. 사용자의 재검토에 따라 반복 횟수만 줄이거나 직접 서술로 일괄 교체하는 방식도 공통 처방으로 삼지 않습니다. 실제 운영 기준은 [작성 방법의 보완 절](../EDITORIAL_METHOD.md#연구-이력과-주장-강도의-점검--2026-10-26-보완)과 [문체 감사](./writing-style-audit-harness.md#과학적-주장과-문체를-함께-점검한다)에 둡니다.
- 적용 한계: 이 게시물은 저자의 경험에 따른 작성 조언입니다. 모델 학습이 특정 문체를 만들었다는 설명은 검증된 인과 결과로 인용하지 않으며, 문장 패턴으로 AI 작성 여부를 판정하지 않습니다. 논문용 구성·실험 조언을 모든 리뷰·렉처·브리핑의 고정 형식이나 새 실험 의무로 바꾸지 않습니다.
- 유지할 기준: 사용자의 현재 지시, 기존 편집·과학 검증 원칙, 김현중식 문체를 우선합니다. 해석에 필요한 조건·불확실성을 삭제하지 않고, 이 글을 개별 과학적 사실이나 수치의 근거로 대신 쓰지 않습니다. 외부 참고의 등록은 기존 게시물을 재작성하거나 과거 검수 이력을 바꿨다는 뜻이 아닙니다.

## 요약 소개문 참고 · 2026-10-27

사용자가 제공한 Quanta의 준리만가설 기사 소개 화면은 전문가의 실제 비판과 수학적 성과, 오래된 아이디어의 새로운 결합을 이어 독자의 관심을 만든다. 확인 범위는 첨부된 소셜 소개문이며 이를 전체 기사 분석이나 외부 매체의 공식 작성 지침으로 확대하지 않는다. 강한 비판 뒤 반전을 모든 요약에 복제하지 않고, 각 글에 실제로 존재하는 사건·어려움·발견과 의미를 살피는 참고로 쓴다. [우리 요약 검토와 수정 사례](writing-reviews/2026-10-27-summary-entry/README.md)와 [공통 요약 감수](writing-style-audit-harness.md#허브-요약과-독자가-들어오는-문장)를 함께 참고한다.

## 참고할 수 있는 선택지

이번 글에 도움이 되는 항목을 고릅니다. 각 항목의 순서는 본문의 전개 순서를 정하지 않습니다.

1. 독자가 아는 장면에서 시작하는 방법
   - 좋은 글은 쉬운 비유로 시작해도 개념을 얕게 만들지 않습니다.
   - 업무, 실험, 문서 검토, 코드 리뷰, 제품 운영처럼 독자가 떠올릴 수 있는 장면을 먼저 둡니다.

2. 전문 용어를 독자의 지식과 연결하는 방법
   - 낯선 핵심 용어는 독자가 해당 주장을 이해할 수 있는 위치와 깊이로 설명합니다.
   - 이미 통용되는 용어는 리뷰 안에서 새로 정의하지 않고, 현재 쓰임과 짧은 계보를 제시합니다.

3. 제목은 작업자의 분류보다 독자의 takeaway를 먼저 말합니다.
   - 피함: `참고자료로 본 쟁점`
   - 권장: `AI 경쟁은 모델 바깥의 작업 환경으로 넓어지고 있습니다`

4. 그림은 장식보다 이해 장치에 가깝게 씁니다.
   - Quanta식 hero는 주제를 열고, Horizon식 도입 그림은 개념을 친근하게 만들고, Science Note식 카드/뉴스레터 감각은 시의성을 잡는 데 씁니다.
   - 도식은 실제 가독성을 확인합니다. 긴 문장, 작은 글자, 겹치는 화살표가 있으면 실패입니다.

5. 한국어 문장은 주어와 행위 주체를 정확히 둡니다.
   - 에이전트가 하는 일, 하네스가 제공하는 구조, 사람이 승인하는 일, 조직이 정하는 정책을 섞지 않습니다.

## 사용 절차

리뷰 초안이나 재작성에서 외부 참고가 필요하면 아래 질문 중 도움이 되는 것을 살펴봅니다.

| 점검 항목 | 질문 |
|---|---|
| Quanta 참고 | 이 글에 필요한 hero나 중간 figure는 무엇인가? 추상 개념을 어떤 장면으로 보여줄 수 있는가? |
| HORIZON 참고 | 독자가 들어올 수 있는 한국어 질문이나 일상/업무 장면은 무엇인가? |
| Science Note 참고 | 이 기술 변화가 지금 왜 중요하고, 조직·산업·정책 맥락에서는 어떤 질문으로 읽히는가? |

리뷰 후에는 아래를 확인합니다.

- 선택한 도입이 이번 주제와 독자, 저자의 의도에 어울리는가?
- 기술어의 설명이 독자의 전제 지식과 논증에 맞는가?
- 제목이 이번 글의 대상·질문·주장·분위기를 적절하게 전달하는가?
- figure가 실제 화면에서 읽히는가?
- 글이 매체 흉내에 머물지 않고 AI_Tech_Review의 기술 검토 목적에 맞게 정리되었는가?

## 주기적 갱신

- 월 1회 HORIZON 최신 글 3편을 확인하고, 새로 배울 만한 도입·전환·전문용어 설명 패턴을 [horizon-style-patterns](./horizon-style-patterns.md)에 추가합니다.
- 분기 1회 Quanta와 Science Note도 함께 훑어 figure 배치와 뉴스레터형 프레이밍을 점검합니다.
- 특정 리뷰 작성 전에는 해당 주제와 가까운 글만 빠르게 참고합니다. 모든 리뷰에서 외부 스타일 분석을 길게 반복하지 않습니다.
