# 콘텐츠 갱신과 최근 글 표시 감수

2026-10-27 · 구현과 로컬 검증 완료, 공개 배포는 배포 기록으로 확인

독자 흐름은 알림 또는 앱 복귀 → 최신 본문 확인 → 최근 변경 인식 → 열람 후 표시 정리이다. 기존 R 브랜드와 본문·표지·PDF는 유지한다.

- `/root/freshness_audit`: 서비스 워커 원인 확인·수정 및 독립 동작 검사. 알림의 동일 URL 분기가 예전 DOM을 포커스만 하던 결함을 확인했다. HTML과 카탈로그의 HTTP 캐시 수명도 확인했다. 실제 OS 알림 전달을 새로 시험한 것은 아니다.
- `/root/update_design_review`: 실제 렌더링으로 시각·인터랙션·접근성 감수. 한영·밝음/어두움, 320·390px에서 넘침 없음. 표시 대비 5.75:1/7.71:1. 실제 글 열기·뒤로 가기·언어 전환의 표시 소거 확인. 설치 모드의 새로고침 대체 버튼은 접근성 이름과 44×44px 영역을 갖는다.
- `/root/update_manifest`: 출판 메타데이터 구현 및 독립 코드 감수. 판본·읽음 조건, 무한 갱신 방지, 카탈로그 호환성과 콘텐츠 보존을 확인했다.
- `/root`: 의견 통합·구현, 통합 검사와 공개 반영 담당.

날짜 옆의 작은 `새 글`·`업데이트` 표시를 채택했다. 실제 최신 HTML 판본의 열람으로 지우며 한영판은 같은 글로 본다. 읽지 않아도 변경 후 7일에 만료한다. 알림 숫자와 기록은 기존 확인 규칙을 유지하고 카드 표시와 분리한다. 화면을 가리는 홍보·미확인 숫자·점멸을 추가하지 않는다. 본문을 읽고 있으면 작고 닫을 수 있는 갱신 안내만 보이며 상단으로 돌아오면 최신 판본을 연다. 일반 탭의 기본 당김 동작을 유지하고 설치 앱에만 당김과 작은 하단 대체 아이콘을 제공한다.

최종 자동 검사: 프런트엔드 145 통과·기존 브라우저 검사 8 제외, 출판 28, 허브·번역 19, 아카이브 30, 검색 출판 3, 개인정보 6 통과. 공개 파일 1,620개/푸시 게시물 52개 검증. 95개 HTML에서 독자 기능 구간 밖의 차이는 두 허브의 JS 버전 링크뿐이다.

실제 브라우저에서는 최신 글 진입·읽음 저장·복귀 표시 소거와, 로컬 시험 응답을 사용한 읽는 중 갱신 안내·위치 보존을 확인했다. 캡처는 `output/playwright/design-*.png`와 로컬 QA에 둔다. 로컬 API CORS 실패는 운영 API의 원점 제한에 따른 것으로 분리했다.

물리 iPhone의 당김과 알림 탭, VoiceOver는 이번 자동 검사로 검증했다고 주장하지 않는다. PDF 뷰어는 HTML 읽음 코드를 실행하지 않으므로 PDF 단독 자료의 표시는 기간 만료를 따른다. 독자 상태는 해당 기기·브라우저에 저장된다. 푸시 대상·알림 생성 기준을 변경한 작업은 아니다.
