# 독립 도식·출력 감수 · 2026-11-03

검토 역할은 `legacy1103_output`이다. 대상은 「AI 처리장치 스택: CPU, GPU, TPU, NPU, LPU는 왜 나뉘는가」 한 편이다. 이번 역할은 도식의 의미·읽는 순서, 실제 브라우저 출력, 접근성과 파일 보존을 확인했다. 원 논문 전체의 과학 감수와 실제 HTTPS 배포 확인은 각각 다른 역할의 기록을 따른다.

## 도식의 의미와 수정

그림 2의 원 공통 좌표는 CPU의 제어·분기와 반복 연산 축의 배치가 충돌하고 서로 다른 처리장치의 효율을 한 위치로 비교하는 인상을 주었다. 수정본은 여덟 역할을 같은 크기의 카드로 병치한다. 카드 위치와 크기가 성능을 나타내지 않는다는 설명과 역할별 검토 조건을 함께 읽었다.

그림 7의 원 상승 곡선은 CPU에서 QPU·wafer-scale·analog까지 공통 효율이 높아지는 순위를 암시했다. 수정본은 연산·정밀도, 데이터 위치, 실행·통신의 세 선택을 나란히 놓고 기대하는 변화와 평가 조건을 구분한다. 행렬 배열이나 낮은 정밀도만으로 산술 연산 횟수가 줄어든다고 읽히던 문구는 `연산 처리 효율·전송량 개선`으로 고쳤다. 최종 실제 렌더에서 이 문구를 다시 확인했다.

그림 4의 Remotion 정적 그림은 보존했다. 원 연결선이 TPU→DPU→QPU 또는 LPU→QPU의 실제 실행 순서·배선처럼 보일 수 있어 캡션에 개념적 작업 배치라는 범위를 명시하도록 제안했고 반영을 확인했다. PNG를 다시 생성하거나 실제 버스·장치 간 직접 연결의 증거로 취급하지 않았다.

수정된 SVG 두 개를 브라우저에서 원 캔버스 크기로 렌더링해 글자·패널 경계를 직접 확인했다. 그림 2의 텍스트 43개와 그림 7의 텍스트 31개가 캔버스와 해당 카드에 들어가며, 카드 오른쪽 여백이 12 SVG 단위보다 작은 항목이나 텍스트 넘침은 없었다. 최종 그림 7의 수정 문구도 같은 검사와 전체 렌더 재확인을 통과했다. 생성 개념 일러스트 4개와 Remotion PNG의 원래 모습도 직접 열람했다.

## 실제 HTML과 키보드 확인

로컬 공개 산출물을 실제 Chrome의 320·390·1440px 폭에서 확인했다. 각 폭에서 문서 전체 너비가 뷰포트와 같고, 기존 그림 7개가 모두 정상 로드됐다. 제목·6월 근거 기준일·11월 개정 기록, 최종 AMD Versal SoC 문장과 그림 캡션을 새로고침한 최종 문서에서 읽었다.

그림 2·4·7은 그림 안쪽에서만 가로 이동한다. 도식은 880px 이상으로 표시하며 캡션과 이동 안내는 바깥에서 문서 폭에 맞춰 읽힌다. 세 영역의 `role=region`, 구별 가능한 접근성 이름, `tabindex=0`, 실제 포커스 테두리를 확인했다. 세 화면 폭 모두에서 영역에 포커스를 둔 뒤 ArrowRight로 가로 이동했다. 390px에서는 세 영역 각각을 키보드만으로 왼쪽 끝 0→오른쪽 끝 556→왼쪽 끝 0까지 이동해 마지막 카드와 연결 영역을 확인했다. 문서 자체는 가로로 움직이지 않았다.

모바일과 데스크톱 첫 화면, 도식의 양 끝과 캡션, 참고문헌의 처음·끝을 실제 캡처로 확인했다. 22개 참고문헌 ID와 27개 숫자 인용 앵커의 대상을 확인했으며, 문서 안의 조각 링크에 없는 대상은 없었다. 이 검사는 모든 외부 출처 서버의 접근 가능성을 검사하거나 사람 독자의 이해도를 측정한 것이 아니다.

판정은 **로컬 최종 출력과 독립 도식 감수 통과**다. 사진·그림을 새로 생성하거나 추가 게시물을 수정하지 않았다. QA 화면과 중간 HTML은 비공개로 보관하며 배포물에 포함하지 않는다. 실제 게시·배포 커밋·공개 URL 검증은 총괄의 진행 기록에서 별도로 확인한다.
