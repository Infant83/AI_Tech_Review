# DQB 일일 점검과 리뷰 기획

설정일: 2026-10-27. 기존 글을 오래된 순서로 개편하는 예약과 별개로, 매일 수신되는 Daily Quantum Brief를 검토하고 관심 주제와 기사 기획을 발전시킨다. 실행 예약과 알림 설정의 정본은 Codex 앱의 예약 작업이다. 이 문서는 조사 방법과 발행 경계를 남긴다.

## 매일 이어갈 작업

1. 최신 사용자 지시와 `AGENTS.md`, `EDITORIAL_POLICY.md`, `EDITORIAL_METHOD.md`, `SCIENTIFIC_EXPLANATION_DIRECTION.md`, `REFERENCE_STYLE.md`, `.automation/writing-style-audit-harness.md`를 확인한다. `archive/manifest.json`, `site/manifest.json`과 기존 `daily_research_review/` 기획도 확인해 이미 다룬 문제를 파악한다.
2. 연결된 메일 도구에서 DQB를 조회한다. 최초에는 최근 7일을 대조하고, 이후에는 마지막 성공 조회보다 7일 앞선 시점부터 겹쳐 조회해 지연 도착·정정 메일을 잡는다. 첨부 원문을 실제로 읽고, 호 날짜와 파일 해시·개정 관계로 중복을 구분한다. 같은 날짜의 새 첨부도 이전 자료와 비교한다. 목록 발견, 원문 확보, 내용 대조, 공개 등록은 서로 다른 상태다.
3. DQB를 탐색의 출발점으로 삼아 연결된 원 논문·보충자료·공식 코드와 관련 선행·후속 연구를 확인한다. 관련 연구는 단순한 키워드 유사성보다 연구 질문·물리적 메커니즘·방법·증거·미해결 문제로 연결한다. 기존 리뷰와 가까운 부분과 새로 설명할 부분을 판단한다. 전자구조·재료·OLED, 양자 알고리즘·소프트웨어·하드웨어, AI를 이용한 과학 연구 등은 초기 관심 지형이며, 새로운 목록이나 고정 분량을 강제하지 않는다.
4. 누적 관심사에 근거·반례·연결·열린 질문을 보탠다. 현재 집중할 주제와 탐색 중인 주변 주제를 구별하고, 새 근거가 있을 때만 범위와 우선순위를 조정한다. 당일 새 자료가 없어도 남은 질문을 진전시킬 수 있으나, 매일 새 주제·새 리뷰·새 기획안을 만들 의무는 없다. 오래된 기획의 진행 상태는 현재 게시 목록과 다시 대조한다.
5. 기획 가치가 충분해지면 후보의 가제, 중심 질문·논지, 독자가 읽을 이유, 기존 리뷰와의 차이, 주요 원문·판본, 설명할 범위와 남은 확인 사항, 필요한 그림·작은 검증의 범위를 담아 제안한다. 원문의 보고 결과와 리뷰 해석·후속 연구 제안을 구별한다. 과학·편집 적합성은 별도 감수 역할과 교차 확인한다.

## 발행과 승인

새 DQB의 공개 보관본과 브리핑·아카이브 목록은 기존 절차에 따라 갱신한다. 원 메일과 개인 식별정보는 공개하지 않는다. `archive/README.md`의 전체 PDF·메타데이터·URI·첨부·실행 동작·개인정보 검사와 PDF 렌더 검수를 완료한 뒤에만 등록한다. 공개용 삭제나 정정이 필요하면 원본과 보관본을 구별하고 과학 본문·수치·원문 링크와 원저자 크레딧을 유지하며 수정 내용을 기록한다. 검수나 재배포 조건이 해결되지 않은 자료는 비공개로 보존하고 등록을 보류한다.

**신규 심층 리뷰는 구체적인 기획안과 필요하면 검토 가능한 초안을 준비해 제안하고, 공개 게재 전에 사용자의 명시적 승인을 받는다.** 무응답·시간 경과·예약 설정을 승인으로 해석하지 않는다. 승인 대기 중에도 매일 자료 확인과 관련 연구 조사는 계속한다. 같은 제안을 날마다 되풀이하지 않고, 유의미한 근거·범위 변화가 있을 때 갱신한다. 승인된 주제·범위와 상태는 비공개 진행 기록에 남기고, 이미 게시했거나 철회한 기획을 다시 발행하지 않는다. 기존 본문의 실질적 확장도 사용자 지시 범위에 맞춰 제안한다.

신규 리뷰를 진행할 때에는 과학 글의 기본 구성, 주제에 맞는 자연스러운 전개와 저자의 관점, APS 인용 순서·원제·원저자·판본을 유지한다. `COVER_ART_DIRECTION.md`를 읽고 필요한 한영 본문·표지·PDF·아카이브·실제 노출 요약을 현행 발행 절차로 검수한다. 영상은 요청이나 설명상 필요가 있을 때만 기획한다.

## 진행 기록과 재개

메일 식별자·원본·첨부 해시·수신 이력, 조회 범위·페이지 처리 상태, 자료별 단계, 기획·승인·게시 이력과 관심사 지도는 예약에 지정한 저장소 밖의 비공개 폴더에 보관한다. 공개 Git과 사이트에는 원 메일·개인정보·비공개 링크·내부 절대경로·QA 화면을 넣지 않는다. 첨부 읽기 실패를 조사 완료로 표시하지 않으며, 조회 성공과 개별 자료 처리 성공을 따로 기록한다. 재개할 항목과 실패 원인을 보존하고, 놓친 실행은 새로운 메일을 빠뜨리지 않는 통합 점검으로 회복한다.

다른 예약이나 사용자의 미완성 변경을 섞지 않는다. 공개 등록·배포가 필요한 경우 최신 원격 기준의 깨끗한 checkout 또는 전용 managed worktree를 사용한다. 해당 DQB 보관·목록 또는 승인된 리뷰에 필요한 출판 원본·검토된 자산·공개 가능한 검수 기록만 커밋하며, 문서 내용 검사·공개 배포 검사와 실제 공개 URL 확인까지 통과해야 배포 완료로 표시한다.

보고에는 새 DQB 수집·공개 보관 상태, 관심사나 판단이 달라진 점, 충분히 준비된 기획 제안과 승인 필요 여부를 짧게 남긴다. 새 메일이 없거나 제안 가치가 아직 부족하면 그 사실만 간단히 기록한다. 메일 발송이나 외부 메시지·테스트 푸시는 이 예약에 포함하지 않는다.
