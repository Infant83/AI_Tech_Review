# 캡스톤: 양자 머신러닝의 성능 주장에 필요한 증거 만들기

이 문서는 원 수업의 과제 복제가 아니라, [독립 실습](../labs/README.md)을 확장하도록 새로 설계한 세 프로젝트다. 각 프로젝트는 2–4주 규모이며 하나를 골라 완결해도 된다. **양자 우위가 없는 결과, 오차 완화가 실패한 결과도 설계와 분석이 정확하면 높은 점수를 받을 수 있다.** QPU 계정·유료 실행은 필수 조건이 아니다. 물리 장치를 사용하지 않으면 보고서의 실행 수준을 고전 시뮬레이션으로 표시한다.

공통 제출물은 문제 정의 1페이지, 식·가정과 비교 계획, 실행 가능한 코드·고정 환경, 재현 명령, seed별 원시 수치, 최종 보고서 6–10페이지다. 공개 가능한 합성·오픈 데이터만 포함한다. 모델 선택에 사용하지 않은 최종 시험 집합을 보존하고, 실행 전 정한 설정과 결과를 보고 변경한 설정을 구별한다. 비공개 계정·credential·장치 토큰·내부 경로는 제출하지 않는다.

## 프로젝트 A. 데이터 인코딩이 만드는 정보 손실과 분류 성능

**핵심 질문:** 진폭·각도·재업로드 인코딩의 성능 차이는 어떤 정보가 남는지, 어떤 고전 feature와 같은지로 설명할 수 있는가?

Lab 2·3을 출발점으로 데이터 세 종류를 만든다. 첫 번째는 `label=sign(x0x1)`인 방향 과제다. 두 번째는 방향을 유지하고 노름만 달리해 label을 정하는 방사형 과제다. 세 번째는 전역 부호로 label이 바뀌는 과제다. 각 데이터에서 진폭 encoding, 각도 encoding, `angle → trainable rotation → angle` 형태의 두 번 data re-uploading을 비교한다. 데이터 크기는 train 40/80/160, validation 80, final test 400 이상으로 하고 최소 5개 seed를 사용한다. 수치는 제안 범위이며 계산 예산에 맞게 실행 전에 수정해도 된다.

비교 기준에는 선형, RBF kernel, 원 feature의 적절한 다항식·삼각함수 모델을 포함한다. 모든 모델의 하이퍼파라미터 선택에 같은 validation 데이터와 명시한 탐색 예산을 준다. 정확도뿐 아니라 balanced accuracy, 파라미터 수, kernel 계산 수, 샷 가정, 학습·시험 데이터 크기를 보고한다. 실행 시간은 환경과 반복 횟수·warm-up을 함께 기록하며 작은 NumPy 최적화 차이를 양자 계산 속도로 해석하지 않는다.

최종 산출물에는 “같은 양자상태인데 다른 정답을 갖는 입력 쌍”을 최소 하나 제시한다. 충돌이 있는 인코딩에서 classifier를 아무리 복잡하게 해도 회복할 수 없는 정보가 무엇인지 논증한다. 노름을 별도 고전 입력으로 주는 hybrid 모델을 추가하고 정보가 복구되는지 측정한다.

| 평가 항목 | 배점 | 충족 조건 |
|---|---:|---|
| 정보 손실에 대한 수학적 설명 | 25 | 전역 위상·정규화·주기성을 구별하고 충돌 예제 증명 |
| 비교 설계와 데이터 분리 | 25 | 같은 분할, 검증 기반 선택, 시험 누수 없음 |
| 구현과 수치 검증 | 20 | 상태 정규화·kernel PSD·독립 해석식 대조 |
| 반복 결과와 비용 보고 | 20 | seed 분포, 표본 크기, 자원 정의, 강한 고전 기준 |
| 해석과 재현성 | 10 | 입증·미입증 범위, 명령·환경·코드 일치 |

**해설 힌트:** 진폭 encoding에서는 `|v⟩`와 `|−v⟩`의 density matrix가 같다. 동일한 density matrix에 대한 모든 POVM의 분포도 같으므로, 부호로 label이 바뀌는 대칭 균형 데이터에서 이 encoding만 사용하는 모델은 두 label을 구별할 수 없다. 이는 optimizer 실패가 아니다. 각도 encoding의 원래 fidelity kernel은 삼각함수 feature의 고전 내적으로 펼칠 수 있다. re-uploading이 늘린 Fourier 성분과 같은 고전 feature 기준을 비교해야 “표현력이 증가했다”는 해석이 구체적이다. Lab 3의 기준 실행에서 고전 RBF와 VQC의 평균 정확도는 모두 0.91875였지만, 그 값은 새 데이터·튜닝의 목표 점수가 아니다.

## 프로젝트 B. 유한 샷 kernel과 VQC의 동일 예산 비교

**핵심 질문:** 데이터·회로·측정 예산을 고정하면 kernel과 VQC 중 어디에 자원이 쓰이며 성능이 어떻게 변하는가?

같은 합성 분류 문제에서 `Ntrain=(20,40,80)`과 샷 예산 `(10⁴,10⁵,10⁶)`의 작은 격자를 먼저 정한다. Lab 4의 회로 장부를 확장해 kernel 구축, VQC forward·gradient·시험 예측, calibration, hyperparameter 탐색을 따로 센다. 모든 비용을 하나로 숨기지 말고 무엇이 총 예산에 포함되는지 명시한다. kernel은 대칭 pair를 재사용하고, noisy diagonal을 측정할지 이상값으로 고정할지 미리 결정한다. VQC는 총 회로 수가 예산을 넘으면 batch·iteration·샷을 어떻게 줄일지 정한다.

Lab 3의 exact kernel을 성공확률로 사용해 각 원소를 유한 샷 이항 샘플링한다. 그 결과를 대칭화하고 고유값을 조사한다. PSD projection을 쓰는 경우 음수 고유값을 0으로 자르는 것이 원래 추정기와 학습 문제를 어떻게 바꾸는지 기록한다. projection 뒤의 대각 재정규화 여부도 명시한다. VQC도 ±1 outcome의 유한 샷으로 forward와 parameter shift를 추정한다. 같은 데이터 seed 안에서 shot seed를 최소 10개 바꿔 데이터 표본 불확실성과 측정 불확실성을 분리한다.

오프라인 계산만으로 완결할 수 있다. QPU를 추가한다면 [결과 템플릿](../labs/qpu_submission_template.json)의 실제 값을 기록하고 컴파일 자원과 물리 결과를 따로 보인다. 제출 스크립트는 기본 실행에서 클라우드 요청을 보내지 않게 분리한다. queue는 timestamp에서 측정한 값만 결과로 쓰고, 가정값은 시나리오 분석에만 쓴다.

| 평가 항목 | 배점 | 충족 조건 |
|---|---:|---|
| 동일 예산의 명확한 정의 | 25 | 학습·추론·튜닝·calibration 비용 포함 여부 명시 |
| 유한 샷 kernel 처리 | 20 | sampling, 대칭, PSD와 projection 영향 구별 |
| VQC 측정·최적화 구현 | 20 | 독립 shift sampling, 총 요청 횟수 정확 |
| 실험 설계·오차 분석 | 20 | 여러 데이터/shot seed와 동일 분할, 편향 포함 |
| 재현성과 실행 수준 표시 | 15 | 재실행 코드와 실제 QPU·가정 시간의 분리 |

**해설 힌트:** 이상적인 pure-state kernel의 diagonal은 1이지만 finite-shot overlap 구현이나 실제 noisy channel에서 diagonal을 무조건 1로 놓으면 다른 추정 문제를 풀게 된다. train pair 수는 off-diagonal만 재사용할 때 `N(N−1)/2`, test 비용은 `Ntest N`이다. VQC의 두 회로 parameter shift 비용은 독립 파라미터당·샘플당·측정 group당 두 설정이며 반복 학습비가 붙는다. Gram matrix 원소별 unbiased sampling도 PSD를 보장하지 않는다. PSD 보정은 유효한 학습 규칙일 수 있으나 quantum advantage의 증거는 아니다. 단일 회로의 작은 표준오차가 전체 Gram matrix나 gradient의 안정성을 자동으로 보장하지 않는다.

## 프로젝트 C. 오차 완화가 이득이 되는 영역과 실패하는 영역

**핵심 질문:** 같은 총 샷에서 readout mitigation과 ZNE가 언제 RMSE를 줄이고 언제 늘리는가?

Lab 5의 스칼라 모형으로 시작해 noise rate `(0.01,0.04,0.12,0.24)`, 총 과학 샷 `(300,3000,30000)`, calibration 샷 `(1000,10000,40000)`을 조사한다. 이 숫자는 사전 계획이며 예산에 맞는 더 작은 격자로 줄여도 된다. scale `(1,2)`의 선형 ZNE와 `(1,2,3)`의 이차 ZNE, readout 보정만, raw를 비교한다. 각 셀에서 calibration·science를 모두 새로 뽑는 500회 이상 Monte Carlo를 수행한다. raw와 보정 추정기의 RMSE·bias·variance를 같은 이상값에 대해 계산한다.

이차 외삽의 샷 배분을 동일 배분과 `|ci| sqrt(Var_i per shot)`에 비례하는 배분으로 비교한다. oracle 분산을 썼는지 pilot 샷으로 추정했는지, pilot 비용을 포함했는지 구별한다. 이상값을 기준으로 scale을 사후 선택하는 절차를 실용적인 방법이라고 소개하지 않는다.

다음으로 `E(s)=E0 exp(−λs)+δs²` 같은 단순 모형 변경이나 scale 사이의 readout drift를 넣는다. 모형이 깨질 때 보정이 좋아 보이는 평균값과 실제 RMSE가 어떻게 어긋나는지 보여 준다. 선택적으로 density matrix에 depolarizing·amplitude damping 채널을 적용한 작은 회로로 확장하되, noise scaling을 실제로 어떻게 구현했는지 명시한다. 고전 density-matrix 실험은 물리 하드웨어 결과로 표시하지 않는다.

| 평가 항목 | 배점 | 충족 조건 |
|---|---:|---|
| 추정기·noise 가정의 정확성 | 20 | assignment 방향, 외삽 계수, 독립성 가정 명시 |
| 총 예산 비교 | 20 | calibration·pilot·science 비용 일관성 |
| 편향·분산·RMSE 분석 | 25 | 무작위 calibration 포함, 반복 수·불확실성 보고 |
| 실패 영역과 모형 변화 | 20 | 저잡음·적은 샷·drift 등 반례 포함 |
| 재현성과 주장 경계 | 15 | 물리 scaling·QEC 미입증을 정확히 구별 |

**해설 힌트:** Lab 5의 quadratic Richardson 계수 `(3,−3,1)`은 `Σci=1`, `Σci si=0`, `Σci si²=0`을 만족한다. 독립 추정치일 때 분산은 `Σci²Vi`이므로 noise가 작아 이미 편향이 작은 조건에서는 추가 분산 때문에 ZNE가 더 나빠질 수 있다. 동일 분산을 가정하면 계수 제곱합은 19다. 고정 총 샷 S에서 `Vi=vi/Si`라면 Lagrange multiplier로 `Si∝|ci|sqrt(vi)`가 나온다. Lab 5의 calibration을 고정한 반복은 전체 calibration uncertainty를 포함하지 않았으므로 본 프로젝트에서는 이를 고쳐야 한다. 보정 확률을 잘라내는 postprocessing을 썼다면 그로 생긴 bias까지 RMSE에 포함한다.

## 최종 구두 검토 질문

1. 결과의 어느 부분이 실제 실행이고 어느 부분이 가정·해석인가?
2. 고전 모델을 더 강하게 바꿔도 결론이 유지되는가?
3. 인코딩·상태 준비·kernel 구축·측정·보정 비용 중 빠진 것은 무엇인가?
4. 같은 결과를 얻기 위해 필요한 데이터와 총 샷이 얼마인가?
5. 어떤 반례나 분포 이동에서 내 결론이 깨지는가?
6. 다른 사람이 새 환경에서 같은 명령으로 표와 그림을 만들 수 있는가?

프로젝트의 성공 기준은 유리한 정확도 한 줄을 얻는 것이 아니라, 선택한 모델이 무엇을 계산했고 어떤 조건에서 유용했는지 다른 사람이 확인할 수 있게 만드는 것이다.
