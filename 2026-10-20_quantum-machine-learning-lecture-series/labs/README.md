## Lab 1. Bell 상태와 미분 가능한 회로

**질문:** 측정 결과의 상관을 보았다는 것과 양자 코히런스를 확인했다는 것은 어떻게 다른가? 회로를 두 번 이동시켜 미분을 구할 수 있는 이유는 무엇인가?

```sh
python labs/qml_labs.py --lab 1
```

기저 순서는 `|q0 q1⟩ = |00⟩, |01⟩, |10⟩, |11⟩`이며 q0가 최상위 비트다. `H(0)`와 `CNOT(0,1)`로 

\[
|\Phi^+\rangle=(|00\rangle+|11\rangle)/\sqrt2
\]

를 만든다. 이상적인 Z 측정 확률은 `(1/2,0,0,1/2)`다. 기준 실행의 4,096회 독립 샷은 `(2110,0,0,1986)`이다. 정확한 기댓값은 `⟨Z0⟩=0`, `⟨Z0Z1⟩=1`, `⟨X0X1⟩=1`이다. 대각 혼합상태 `ρ=(|00⟩⟨00|+|11⟩⟨11|)/2`도 같은 Z 분포를 내지만 `⟨X0X1⟩=0`이다. 따라서 Z counts만으로 얽힘을 인증했다고 쓰면 안 된다. 여기서는 상태벡터와 혼합상태의 정확한 계산으로 차이를 확인했으며, 유한 샷 얽힘 witness의 통계적 인증은 수행하지 않았다.

다음에는 단일 큐비트 `Ry(θ)|0⟩`에서 `f(θ)=⟨Z⟩=cos θ`를 계산한다. `Ry(θ)=exp(-iθY/2)`의 생성자 고유값은 ±1/2이므로

\[
f'(\theta)=\frac{f(\theta+\pi/2)-f(\theta-\pi/2)}2=-\sin\theta.
\]

`θ=0.73 rad`에서 해석 미분 `-0.6668696350`, parameter shift `-0.6668696350`, 중앙 유한차분 `-0.6668696351`이 일치한다. 이동한 두 회로에 각 4,096샷을 쓰면 seed 101의 추정값은 `-0.6774902344`, 알려진 모형에서 계산한 표준오차는 약 `0.0082331`이다. 한 번의 무작위 추정값은 정확한 미분과 일치할 필요가 없다.

**직접 할 일:** θ를 0, π/2, π로 바꾸고 확률·기댓값·분산의 관계를 기록한다. 샷 수를 네 배로 늘렸을 때 표준오차가 약 절반인지 반복 실험한다. 생성자의 스펙트럼이나 한 파라미터의 다중 게이트 공유가 바뀌어도 이 단순한 두 회로 공식을 그대로 적용할 수 있는지 조사한다.

## Lab 2. 인코딩은 어떤 정보를 없애는가

**질문:** 고전 벡터를 양자상태로 옮겼을 때 원래의 거리와 군집 구조가 보존되는가?

```sh
python labs/qml_labs.py --lab 2
```

두 인코딩을 구분한다.

- 진폭 인코딩은 실수 2차원 벡터 v를 `|v⟩=v/||v||`인 한 큐비트 상태로 바꾼다. 영벡터는 허용하지 않는다. 일반 d차원 데이터에는 2의 거듭제곱 차원으로 padding과 정규화가 필요하며 상태 준비 비용은 이 작은 계산에 포함되지 않는다.
- 각도 인코딩은 두 숫자를 `Ry(x0)|0⟩ ⊗ Ry(x1)|0⟩`에 넣는다. 두 큐비트가 필요하며 각도는 rad 단위다. 2π 주기의 물리적 동일성과 스케일 선택이 데이터의 의미에 영향을 준다.

진폭 상태의 fidelity `K(v,w)=|⟨v|w⟩|²`는 원 벡터의 노름을 없애고 전역 부호도 구분하지 못한다. v와 −v의 fidelity는 1이지만 정규화한 고전 벡터의 제곱 유클리드 거리는 4다. v와 10v도 같은 상태다. 표준 정규화 절차를 작은 기술적 단계로만 생각하면 문제의 목표 자체를 바꿀 수 있다.

코드는 같은 8개 정규화 벡터에 두 가지 Lloyd 반복을 적용한다. 유클리드 k-means는 산술평균 centroid를 사용한다. 여기서 새로 구현한 **projective fidelity clustering**은 `Σ_i[1−|⟨x_i|c⟩|²]`를 줄이며, 각 군집의 `Σ_i |x_i⟩⟨x_i|`의 최대 고유값 고유벡터를 단위 centroid로 선택한다. 이는 Rayleigh quotient의 해다. 목적함수가 다른 알고리즘이므로 유클리드 k-means를 양자적으로 가속했다고 부르지 않는다. `1−K` 역시 일반적인 거리의 삼각부등식을 자동으로 만족하는 metric이라고 가정하지 않는다.

기준 실행의 projective 군집은 `(0,0,0,0,1,1,1,1)`이고 최종 목적함수는 `0.0792079`다. 유클리드 군집은 `(0,0,1,1,1,1,0,0)`이며 목적함수는 `4.0396040`이다. **서로 다른 목적함수의 숫자 크기로 어느 군집화가 더 좋다고 비교하면 안 된다.** 초기 centroid를 고정했으므로 전역 최적해를 보장하지도 않는다.

각도 인코딩의 fidelity는

\[
K(x,y)=\prod_{j=0}^{1}\cos^2((x_j-y_j)/2)
\]

이며, 코드가 게이트 행렬 내적과 이 식을 따로 계산해 확인한다. 예제 쌍에서 `0.2985717802`로 일치한다.

**직접 할 일:** 부호가 의미 있는 데이터와 의미 없는 데이터를 각각 만든다. 노름이 목표값을 결정하는 데이터도 만든다. 어떤 인코딩에서 예측 불가능한 충돌이 생기는지 보이고, 노름·부호를 별도 고전 feature로 보존하는 방법을 제안한다. 상태를 만드는 전체 게이트 수를 모른 채 “n개의 실수를 log₂n 큐비트에 넣으므로 효율적”이라고 결론 내리지 않는다.

## Lab 3. 같은 데이터에서 커널, VQC, 고전 기준 비교

**질문:** 비선형 분류에 도움이 되는 양자 표현을 찾았다는 것과 고전 계산보다 유리하다는 주장은 어떻게 구별되는가?

```sh
python labs/qml_labs.py --lab 3
```

합성 데이터는 독립 균등분포 `x∼U([-1.4,1.4]²)`이며 정답은 `y=sign(x0x1)∈{−1,+1}`이다. seed `(11,23,37,41,53)`마다 새로 뽑은 240개를 앞 80개 학습, 뒤 160개 시험으로 분리한다. 입력 정규화나 feature 선택을 시험 데이터에 맞추지 않는다. ridge λ=0.1, VQC 600회·학습률 0.08은 사전에 정한 교육용 값이고 튜닝 결과가 아니다. 현실 데이터에 대한 일반화 검증은 아니다.

비교 모델은 선형 ridge, 고전 삼각함수 feature ridge, 위 각도 fidelity kernel ridge, 고전 RBF kernel ridge, 두 파라미터 VQC다. kernel ridge는 `α=(K+λI)⁻¹y`를 선형 방정식으로 풀며 prediction은 `K(test,train)α`다. SVM을 구현한 것은 아니다. Gram 행렬의 대칭성·단위 대각·양의 준정부호를 확인한다. 유한 샷 kernel의 음수 고유값과 보정은 이 실습 밖의 확장 문제다.

VQC는 `Ry(x0),Ry(x1) → Ry(θ0),Ry(θ1) → CNOT(0,1) → ⟨Z1⟩`이다. 고전 gain·bias를 포함한 출력은 `g fθ(x)+b`, 학습 손실은 평균제곱오차다. θ의 미분은 parameter shift로 계산하고 g,b는 고전 미분으로 갱신한다. 시험 정답은 학습·조기 종료·파라미터 선택에 사용하지 않는다.

이 회로는 정확히

\[
f_\theta(x)=\cos(x_0+\theta_0)\cos(x_1+\theta_1)
\]

이므로 빠른 고전 식으로 학습한다. 별도의 게이트 행렬 계산을 각 seed의 시험 데이터 10개와 대조한다. 또한 `cos x0 cos x1`, `cos x0 sin x1`, `sin x0 cos x1`, `sin x0 sin x1`의 선형결합으로 정확히 전개되므로 같은 feature를 쓰는 강한 고전 기준도 함께 넣었다. 이 실습의 fidelity kernel도 단순한 두 변수 삼각함수 곱이다. **얽히는 회로를 쓴다는 사실만으로 고전적으로 어려운 모델이 되지 않는다.**

기준 실행의 시험 정확도는 다음과 같다. ±는 다섯 seed 사이의 표본 표준편차이며 신뢰구간이나 우월성 유의성 검정이 아니다. 모든 행은 같은 seed에서 같은 분할을 사용했다.

| 모델 | 시험 정확도 평균 ± seed 표준편차 |
|---|---:|
| 선형 ridge | 0.58625 ± 0.09222 |
| 고전 삼각함수 feature ridge | 0.88500 ± 0.05441 |
| 각도 fidelity kernel ridge | 0.87375 ± 0.05104 |
| 고전 RBF kernel ridge | 0.91875 ± 0.03395 |
| VQC + 고전 gain,bias | 0.91875 ± 0.04122 |

“VQC가 선형 모델보다 잘했다”는 이 합성 데이터의 결과는 맞지만, 고전 RBF와 평균 정확도가 같고 모든 계산을 고전 CPU로 수행했다. 하이퍼파라미터·모델 용량·최적화 방법도 완전히 같은 자원으로 맞춘 비교가 아니다. 시간 우위, 표본 복잡도 우위, 하드웨어 내잡음성은 측정하지 않았다.

**직접 할 일:** 검증 분할을 새로 두고 모든 모델의 λ·RBF 폭·VQC 초기화를 같은 탐색 예산으로 고른 뒤 마지막 시험을 한 번 수행한다. 클래스 균형, balanced accuracy, 학습곡선, 데이터 분포 이동도 보고한다. 양자 모델에만 feature를 유리하게 고르거나 고전 기준을 선형 모델 하나로 제한하지 않는다.

## Lab 4. 샷과 대기시간까지 포함한 하드웨어 실험 설계

**질문:** 작은 VQC의 파라미터 수를 알 때 실제로 요청할 회로·샷 수는 얼마나 되는가?

```sh
python labs/qml_labs.py --lab 4
```

기본 비용 예제는 Lab 3을 그대로 실행한 기록이 아니라 **별도의 가상 workload**다. 파라미터 P=6, batch B=12, 학습 T=25회, 비가환 측정 group G=2, 회로 설정별 S=2048샷이다. 모든 파라미터를 독립적인 두 회로 shift로 미분하고, 각 예제에 forward 회로 하나를 추가한다고 가정하면

\[
N_{\rm settings}=TB(1+2P)G=7800,\qquad
N_{\rm shots}=S N_{\rm settings}=15,974,400.
\]

공유 파라미터의 다중 등장, 회로 캐싱, stochastic gradient, 샷 재사용, adjoint 방식에 따라 다른 식이 필요하다. 측정 group 수는 observable의 통근 관계와 측정 계획에서 결정해야 한다. 코드에서는 인덱스 조합을 실제로 열거해 같은 수를 확인한다.

회로 설정 300개/job, 샷당 50μs, job당 queue 30초와 고정 overhead 0.2초를 **임의로 가정**하면 26 jobs, 샷 실행 798.72초, 직렬 queue 합 780초, overhead 5.2초, 총 1583.92초다. 이는 실제 제공자 측정·견적·예측이 아니다. job의 병렬 처리·재시도, calibration, routing, reset·측정 구성, 데이터 전송·상태 준비 비용에 따라 달라진다. 샷당 시간도 한 회로 길이에 대한 예시일 뿐이다.

같은 파일은 80개 학습 데이터의 이상적 대각을 생략하고 대칭을 재사용하는 kernel 비용도 센다. 학습 비대각 3,160쌍과 test–train 12,800쌍, 합계 15,960회 overlap 설정이다. noisy diagonal을 실제 측정해야 한다면 별도로 추가해야 한다. kernel 구축비와 VQC 학습비를 예측 하나의 비용으로 혼동하지 않는다.

마지막으로 `⟨Z⟩=cos(0.73)`를 128,512,2048,8192샷으로 각각 1,000번 이항 샘플링한다. 이론 표준오차 `sqrt((1−⟨Z⟩²)/S)`와 경험 RMSE를 비교하면 샷 64배가 표준오차 8배 감소에 해당한다.

실제 QPU로 확장할 때는 [qpu_submission_template.json](qpu_submission_template.json)을 새 결과 파일에 복사해 채운다. provider/backend, SDK/plugin 버전, calibration 시각, physical qubit mapping, native gate 수, transpiled depth, job ID, counts, queue/QPU/wall 시간, 비용과 보정 전후 불확실성을 기록한다. `null`은 아직 측정하지 않았다는 뜻이다. **이 템플릿은 제출 코드를 포함하지 않으며 현재 실습은 인증정보를 읽거나 클라우드 작업을 제출하지 않는다.** 실제 실행 조건과 예산을 결정한 뒤 해당 제공자의 공식 문서로 제출 코드를 작성해야 한다.

## Lab 5. 측정 보정과 ZNE가 편향·분산에 미치는 영향

**질문:** 오차 완화로 평균값을 개선해도 더 많은 샷이 필요한 이유는 무엇인가?

```sh
python labs/qml_labs.py --lab 5
```

여기서는 회로의 물리 채널을 시뮬레이션하는 대신, 이상값 `E0=cos(0.73)=0.7451744`와 명시적 스칼라 모형 `E(s)=E0 exp(−0.12s)`를 둔다. noise scale `s=(1,2,3)`에서 이항분포로 ±1 측정값을 만든다. **gate folding, 펄스 늘이기, 실제 장치의 noise scaling을 구현한 것은 아니다.**

먼저 true state 0과 1을 각 20,000샷 준비했다고 가정한 대칭 측정 오류 8% 모형에서 assignment 행렬 A를 추정한다. 행은 observed bit, 열은 true bit이며 `pobs=A ptrue`다. 역행렬 해와 기댓값의 affine correction을 대조한다. 보정은 관측 확률의 통계 변동도 확대하며, A가 특이행렬에 가까울수록 불안정해진다. 결과를 확률 범위나 [−1,1]로 임의 clipping하지 않는다. clipping하면 편향·분산 추정 자체가 달라진다.

ZNE는 세 scale의 보정된 추정치를 `3E(1)−3E(2)+E(3)`으로 합친다. 계수의 합은 1이고 s, s²에 대한 가중합은 0이므로 noise expansion의 첫 두 항을 소거한다. 지수함수에는 더 높은 차수 항이 남는다. 정확한 무샷 결과에서도 ZNE 값은 `0.7440969`, 이상값 대비 편향 `−0.0010775`로 0이 아니다.

각 scale에 과학 측정 4,000샷을 쓰고 1,000회 실험을 반복했다. calibration은 한 번 뽑아 모든 반복이 공유한다. 따라서 아래 표준편차와 코드의 이론 표준오차는 **그 calibration에 조건부**이며 calibration uncertainty를 전파하지 않았다. 반복마다 calibration까지 다시 하는 bootstrap은 확장 과제다. 1,000회 반복은 분포를 교육용으로 추정하기 위한 계산이며, 한 번의 실제 실험 비용과 구분한다.

| 추정기 | 평균 | 이상값 대비 bias | 표본 표준편차 | RMSE |
|---|---:|---:|---:|---:|
| scale 1 raw, 4,000샷 | 0.55517 | −0.19001 | 0.01277 | 0.19044 |
| scale 1 readout 보정, 4,000샷 | 0.65361 | −0.09157 | 0.01512 | 0.09281 |
| readout 보정 + ZNE, 3×4,000샷 | 0.73655 | −0.00862 | 0.06837 | 0.06888 |
| readout 보정만, scale 1에 12,000샷 | 0.65369 | −0.09149 | 0.00907 | 0.09194 |

마지막 행은 ZNE와 같은 총 과학 샷 12,000개를 사용하는 예산 비교다. 두 방법 모두 calibration 40,000샷은 별도이며 같다. ZNE의 분산은 독립 추정치라면 `Σ c_i² Var(E_i)`다. 계수 제곱합은 19이지만 scale별 분산이 서로 달라 정확한 증폭률이 항상 19인 것은 아니다. 이 모형에서는 ZNE가 예산을 맞춘 RMSE도 줄였으나, 작은 noise나 적은 샷에서는 분산 증가 때문에 더 나빠질 수 있다. 오차 완화는 오차 정정이나 내결함성의 증명이 아니다.

**직접 할 일:** noise rate를 0.01부터 0.30까지, 총 과학 샷을 300부터 30,000까지 바꾸어 같은 예산의 RMSE를 비교한다. calibration을 매 반복 다시 추정해 전체 불확실성을 포함한다. 서로 다른 scale 사이에 noise drift를 넣고 선형·이차 외삽 중 어느 쪽이 실패하는지 본다. 원하는 결론이 나오는 scale만 사후 선택하지 않는다.

## 선택 실습: PennyLane과 독립 대조

원 수업의 SDK 입문 주제를 따라가되, 위 NumPy 구현을 독립 기준으로 삼는다. **Python 3.12.14 / PennyLane 0.45.1 / NumPy 2.3.5**로 다음 선택 실습도 실제 실행했다.

```sh
python -m pip install -r labs/requirements-pennylane.txt
python labs/pennylane_compare.py --output labs/results/my-pennylane-results.json
```

`default.qubit`, `shots=None`에서 Bell 상태, parameter-shift 자동미분, `AmplitudeEmbedding(normalize=True)`, 각도 feature overlap, VQC 기댓값을 독립 NumPy·해석식과 비교한다. 이 SDK의 정확한 상태벡터도 물리 하드웨어가 아니다. 보존 결과는 [pennylane-results.json](results/pennylane-results.json), 당시의 전체 설치 버전은 [sdk-lock.txt](sdk-lock.txt)다. 고정 requirements는 실습 재현을 위한 기록이며 이후 최신 지원 버전이라는 주장은 아니다.

SDK 코드의 사용법은 [PennyLane QNode 공식 문서](https://docs.pennylane.ai/en/stable/code/api/pennylane.qnode.html), [parameter-shift 공식 문서](https://docs.pennylane.ai/en/stable/code/api/pennylane.gradients.param_shift.html)를 확인했다. 수식의 출처를 SDK 동작과 혼동하지 않도록 미분 자체는 [Schuld et al., 2019](https://doi.org/10.1103/PhysRevA.99.032331), ZNE의 원리는 [Temme et al., 2017](https://doi.org/10.1103/PhysRevLett.119.180509)을 함께 읽는다. 이 코드가 해당 논문의 실험을 재현하는 것은 아니다.
