OTel 기반 에이전트 추적성 청사진

요즘 “AI 에이전트/툴 호출”을 서비스에 붙일 때 꼭 챙겨야 하는 게 관측(Observability)과 감사(프로비넌스)예요. 한마디로, 에이전트가 무엇을 계획하고 어떤 툴을 어떻게 썼는지 “추적 가능한 기록”을 남겨야 합니다. 아래처럼 하면 깔끔하고, 벤더 중립적으로 여러 백엔드(Datadog/Elastic/Honeycomb 등)로 보내기도 쉬워요.

무엇을 남길까? (핵심 아이디어)

계획 = 루트 트레이스, 각 스텝/툴 호출 = 자식 스팬으로 기록

W3C Trace Context(traceparent/tracestate)로 트레이스 아이디를 표준화

스팬/리소스 속성은 OpenTelemetry(OTel) GenAI/세맨틱 컨벤션에 맞춰 태깅

최소 속성 세트(권장)

식별: trace_id, span_id, parent_id

행위자: actor.id, actor.type (agent | subagent | human)

계획: plan.id, plan.step_id

도구: tool.name, tool.version, tool.call_id

입력: input.sha256, input_ref(저장 위치/키), input_size

출력: output.sha256, output_ref, artifact_id

시간: start_timestamp, end_timestamp

상태: status(ok/error/cancel), result_code

샘플링/보안: sampling_priority, redaction_flags

프로비넌스(출처 서명): provenance.signature

tracestate: 벤더/보관 이관 메타데이터(예: 수탁자, 정책 버전)

이렇게 남기면, 수집기는 별도 파싱 없이 OTLP로 백엔드에 전달할 수 있어요.

데이터 보존(Retention)·프라이버시 권장

원본 입력은 단기 보관: 7–30일 권장(PII 자동 마스킹/삭제)

장기 보관: 해시와 메타데이터만(감사 목적 1–7년, 정책에 따라)

외부로 내보내는 산출물: 서명된 아티팩트 영수증(receipt) 발행 → 누가/언제/무엇을 생성했는지 검증 가능

tracestate에 수탁사/전달 체인 같은 인계 메타데이터 기록

콜렉터에서 샘플링·마스킹·암호화 등 보안 통제 적용

필드 매핑(예시 스키마)

아래는 OTel 리소스/스팬 속성으로 매핑한 예입니다. 이름은 팀 스타일에 맞게 조정하세요.

구현 체크리스트(빠르게 적용)

트레이스 구조: “에이전트 계획”을 루트, 각 계획 단계/툴 호출을 자식 스팬으로.

W3C Trace Context 전파: 내부 gRPC/HTTP 호출마다 traceparent/tracestate 전달.

세맨틱 태깅: 위 최소 속성 세트 + OTel GenAI 규약으로 네이밍 정리.

수집기(OTLP Collector):

파이프라인: receiver(otlp) → processors(batch, attributes, redaction) → exporters(datadog/elastic/honeycomb/otlp).

attributes processor로 PII 제거/마스킹, 샘플링 정책 적용.

보관 정책:

원본 입력은 단기 스토리지(암호화, 수명 종료 자동화).

메타데이터/해시는 장기 보관(감사 규정에 맞춰).

산출물 릴리스 시 서명 영수증을 생성·보관.

보안/컴플라이언스: 키 관리(KMS), 접근 통제(ABAC/RBAC), 전송·저장 암호화, 지역 거버넌스(EU/US 등) 준수.

대시보드: “계획 성공률, 단계별 실패 코드, 평균 스텝 지연, 툴별 오류율, 샘플링 비율” 위젯 구성.

자주 받는 질문(초간단)

왜 해시만 장기 보관? 내용 대신 해시·메타만으로 무결성 증명과 재현성 추적이 가능하고, 개인정보·비밀 유출 리스크를 크게 줄입니다.

tracestate는 왜 써요? 동일 트레이스를 여러 시스템이 넘겨받을 때 수탁·정책 버전 같은 벤더 특화 정보를 안전하게 태깅할 수 있어요.

사후 분석은 충분한가요? 입력 샘플은 짧게 보관하되, 대표 샘플만 추가 보존(익명화)하면 품질/사고 분석에 충분합니다.

원하시면 현재 스택(언어/프레임워크/수집기/백엔드)에 맞춘 OTel 인스트루멘테이션 샘플 코드와 Collector 파이프라인(yaml), 그리고 대시보드 템플릿을 바로 만들어 드릴게요.
