OIDC ID 토큰과 CI Job 토큰 수명 관리

여기, GitLab CI/CD에서 “토큰”이 바뀌고 있다는 핵심만 쭉 정리해 드릴게요—보안/운영에 바로 영향 있습니다.

왜 지금 중요한가

GitLab은 레거시 CI_JOB_JWT*를 폐기하고, .gitlab-ci.yml의 id_tokens(OIDC ID 토큰) 사용을 권장/기본화했습니다. GitLab 17 계열에서 관련 변경이 크게 반영되었어요. 
about.gitlab.com
+1

ID 토큰은 짧게(기본 약 5분) 유효하고, 작업(Job) timeout:을 설정하면 그 시간이 만료 시간으로 반영됩니다. (짧고 예측 가능한 만료가 폭발 반경을 줄입니다.) 
GitLab Docs

**CI_JOB_TOKEN(레지스트리/프로젝트 간 액세스용)**은 잡이 도는 동안만 유효하며, 범위를 Allowlist로 제한해야 합니다. 
GitLab Docs
+1

무엇을 바꿔야 하나 (체크리스트)

.gitlab-ci.yml에 id_tokens를 정의하고 **aud(Audience)**를 반드시 지정하세요. (예: AWS/K8s 등)

민감 잡에 timeout: 명시

ID 토큰 만료가 잡 타임아웃에 연동되므로, 민감 잡은 짧게 설정하세요. 
GitLab Docs

CI_JOB_TOKEN 범위 최소화

Job Token Allowlist를 활성화하고, 필요한 프로젝트만 허용하세요.

“Job token으로 push 허용” 옵션은 정말 필요한 경우에만 켜세요.

최소 예시 (.gitlab-ci.yml)
YAML
deploy:
  image: alpine:3.19
  id_tokens:
    AWS_ID:
      aud: "sts.amazonaws.com"    # 대상 서비스(검증자)에 맞게 설정
  timeout: 10m                     # 민감 잡은 짧게
  script:
    - echo "$AWS_ID" > idtoken.jwt # 필요 시 파일로 넘기기
    # 여기서 OIDC 토큰으로 클라우드 로그인/시크릿 페치 수행

id_tokens는 잡 시작 시 해당 aud로 서명된 JWT를 환경변수/파일로 제공해 줍니다. Vault/Kubernetes/AWS 등과 바로 연동 가능.
