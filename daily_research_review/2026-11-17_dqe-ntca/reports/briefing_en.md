Suppose a quantum algorithm produces the same measurement probabilities after a move to another SDK. Is the port correct? For nonlinear transformations of amplitudes, relative phases and the rule for accepting trials are part of the result too. This DQE expresses a small cubic transformation in PennyLane, Qiskit and Classiq to establish what must be checked together.

The starting point is the PennyLane tutorial Nonlinear transformation of complex amplitudes by Naixu Guo, Rishabh Gupta, Po-Wei George Huang and Yizhan Han.<span class="citation">[<a href="#ref-1">1</a>]</span> It moves amplitudes into a diagonal block and uses QSVT to approximate smooth functions. Guo and colleagues develop the broader NTCA framework.<span class="citation">[<a href="#ref-2">2</a>]</span> Here, a new educational problem uses the block-product perspective discussed by Rattew and Rebentrost to verify a cube exactly, setting aside approximation and phase finding.<span class="citation">[<a href="#ref-3">3</a>]</span>

## Try the problem first

[Open page 1 of the problem PDF](https://infant83.io/AI_Tech_Review/archive/files/2026-11-17-daily-quantum-exercise-ntca.pdf#page=1). Allow about 20 minutes for the concepts and calculations, with optional platform practice afterward. Solutions begin on page 2 and platform instructions on page 4. A reusable state-preparation circuit U and fresh work registers are provided. Calculate the two routes' outputs, acceptance rates and resources, then test the relative phases for a complex input.

The exercise builds a habit that survives a change of software: specifying what is prepared, which bits control a gate, and which trials are retained. Checking the quality of a normalized accepted state together with the cost of all trials also helps design larger quantum machine-learning experiments.

The expandable section contains numerical answers and execution instructions. Open it after trying the problem.

<h3>A fresh work register multiplies amplitudes</h3>
<p>Prepare Σj xj|j⟩ on the work register with U, then XOR address i into it to obtain Σj xj|j XOR i⟩. Selecting work result 00 retains j=i, multiplying address amplitude i by xi. The selected block is D=diag(x). Forward U followed by XOR gives xi, without conjugation, for complex inputs too. Fresh work registers allow these selected blocks to multiply.</p>
<p>For x=(1,2,−1,0)/√6, three filters on a uniform address give the unnormalized accepted branch x³/2. Preparing the address in |x⟩ and using two filters gives x³. Both normalized outputs are (1,8,−1,0)/√66. Their acceptance probabilities are 11/144≈0.076389 and 11/36≈0.305556. For a fixed U, the gates and selected block are linear. Repeated access to an input-dependent preparation circuit, conditioning and normalization produce the nonlinear-looking map. The construction does not assume a deterministic cubic unitary acting on one unknown copy.</p>
<p>The explicit logical registers use eight qubits for the uniform route and six for the input-weighted route. XOR requires six and four CNOTs, excluding the decomposition of U. The filters call U three and two times, but the input-weighted address needs one more preparation, making the total three in either complete trial. With independent complete trials before postselection, expected U calls per accepted result are 3/p: approximately 39.27 and 9.82. Preparation decomposition, extra synthesis workspace and hardware runtime must be counted separately.</p>
<h3>Find an incorrect result with identical probabilities</h3>
<p>For z=(1,i,−1,0)/√3, the correct target is (1,−i,−1,0)/√3. Acceptance probabilities are 1/36 and 1/9. A conventional cubic singular-value transformation of a complex diagonal matrix can yield z|z|² rather than z³. Cubing the real and imaginary parts separately also omits the mixed terms of the complex cube. Those two incorrect constructions produce the same incorrect state for this particular example.</p>
<p>The correct and incorrect states both have computational-basis probabilities (1/3,1/3,1/3,0), yet their mutual fidelity is 1/9. The Y expectation on the least significant address bit is −2/3 for the target and +2/3 for the incorrect result. A shot-based test applies S† followed by H on that bit before a Z measurement. Estimate Y within trials whose work bits are all zero, while separately reporting acceptance over all trials. Acceptance and the conditional mean use different denominators.</p>
<h3>Implement it in PennyLane too</h3>
<p>The PennyLane 0.45.1 implementation uses default.qubit and MottonenStatePreparation to define U through rotations and CNOTs, followed by address-to-work CNOTs.<span class="citation">[<a href="#ref-4">4</a>]</span> Address wires=[0,1] occupy the leading, most significant positions in this code's state vector. Reshape qml.state() into address and work axes and select the single work-index-zero column. Check its norm against qml.probs(work)[0].</p>
<p>In a separate Python 3.12 environment, run <code>python -m pip install -r requirements-pennylane.txt</code>, then <code>python pennylane_ntca_monomial.py</code>. The <a href="https://github.com/Infant83/AI_Tech_Review/tree/main/daily_research_review/2026-11-17_dqe-ntca/artifacts/platforms/pennylane">PennyLane code, pinned requirements and results</a> cover both routes and both real and complex inputs.</p>
<h3>Port the same circuit to Qiskit</h3>
<p>The Qiskit 2.6.2 implementation uses a StatePreparation gate and cx.<span class="citation">[<a href="#ref-5">5</a>]</span> Qiskit bit q contributes weight 2**q to a statevector index, so the PennyLane array slice should not be copied. The supplied code builds full indices from the physical positions of the logical address bits, selects all-zero work amplitudes, and records their squared norm before normalizing.</p>
<p>Run <code>python -m pip install -r requirements-qiskit.txt</code>, then <code>python qiskit_ntca_monomial.py</code>. The <a href="https://github.com/Infant83/AI_Tech_Review/tree/main/daily_research_review/2026-11-17_dqe-ntca/artifacts/platforms/qiskit">Qiskit code, pinned requirements and results</a> check preparation, the diagonal block, complex amplitudes and acceptance, and include a toy gate decomposition. Those gate counts are not hardware latency measurements.</p>
<h3>Create the Qmod model in Classiq</h3>
<p>The Classiq SDK 1.35.0 implementation expresses the same logical module with prepare_amplitudes and CX. That preparation API accepts real amplitudes.<span class="citation">[<a href="#ref-6">6</a>]</span> For the complex example, prepare magnitudes, then apply S to bit 0 and Z to bit 1. Named QNum outputs retain the address and work values, allowing the cloud-statevector helper to use register columns rather than assume a physical qubit layout.</p>
<p>Run <code>python -m pip install -r requirements.txt</code>, then <code>python ntca_classiq.py --output classiq-models</code>. The default creates four models and validates JSON and client schemas locally, without sign-in. Adding <code>--cloud</code> in an already authenticated SDK environment requests synthesis and the Classiq classical simulator's state vector. Classiq cloud synthesis, statevector execution and QPU execution were not performed for this publication. The <a href="https://github.com/Infant83/AI_Tech_Review/tree/main/daily_research_review/2026-11-17_dqe-ntca/artifacts/platforms/classiq">Classiq code and installation, authentication and execution guide</a> separate local model checks from optional cloud execution.</p>
<h3>From a cube to general functions and applications</h3>
<p>A cube emphasizes components with larger amplitudes. An input-mixing circuit, this filter and a later measurement could form a feature layer for a classification study. Changing a trainable parameter requires applying the same complete preparation U to the work registers too. Record acceptance and repetition costs alongside the loss and classification performance. This is a proposed experiment. Four entries are easy to transform classically, making a classical model with the same features and a full accounting of input loading essential starting comparisons.</p>
<p>A general QSVT extension must specify the approximation interval, degree, parity, scale, block normalization and success signal. Check whether input weighting g(t)=f(t)/t admits a bounded extension at zero. PennyLane's low-power-first coefficient convention and the real-part signal documented for qsvt require checking the complete complex block.<span class="citation">[<a href="#ref-7">7</a>]</span> Qiskit needs explicit block, reflection and phase-sequence construction; Classiq's qsvt and qsvt_phases follow their own signal and measurement conventions.<span class="citation">[<a href="#ref-8">8</a>]</span> The executed exercise is an exact monomial block product, not a QSVT run or a reproduction of the original classifier.</p>
