# AI Updates Weekly 하네스 리뷰 김현중식 문체 재감사

## 요약

`audit_review_text.py`에 김현중식 글쓰기 watchlist를 반영한 뒤 현재 `final_review.md`를 다시 검사했다. 기존 자동 감사에서는 문제가 없다고 나왔지만, 새 기준에서는 51개 항목이 잡혔다. 이는 문장이 틀렸다는 뜻이라기보다, 현재 리뷰가 아직 AI식 전개 리듬과 접착어에 많이 기대고 있음을 보여준다.

## 가장 먼저 고칠 구조

1. 초반 참고자료 표의 위치
   - 현재는 도입부 뒤에 곧바로 참고자료 분류표가 나온다.
   - 독자는 아직 하네스 논의가 왜 업무 경험과 연결되는지 충분히 체감하기 전에 자료 배열을 만난다.
   - 표는 유지하되, 먼저 1-2개 구체 업무 장면과 핵심 주제를 더 만든 뒤 배치하는 편이 낫다.

2. 섹션 반복 패턴
   - 여러 섹션이 `출처 설명 -> 하네스 관점 해석 -> 한 문장 결론`으로 반복된다.
   - 일부 섹션은 제품 장면, 코드 작업 장면, 권한 흐름, 병합 장면에서 시작하도록 바꾸는 편이 좋다.

3. 마무리 구조
   - 현재 마무리는 `지금까지 살펴본 자료를 어떻게 읽을 수 있을까요? -> 질문 하나 -> 세 가지 bullet -> 마지막 슬로건` 구조다.
   - 이 구조는 생성형 요약문처럼 보이므로 본문 사례를 회수하는 방식으로 바꾼다.

## 우선 수정할 소제목

| 현재 소제목 | 문제 | 수정 방향 |
|---|---|---|
| `하네스는 모델이 업무를 통과하게 만드는 장치입니다` | `장치입니다`가 설명을 닫는 만능 술어처럼 보임 | 하네스가 어떤 운영 조건을 만든다는 점을 제목에 직접 반영 |
| `에이전트 경쟁은 실행 환경을 함께 묻기 시작했습니다` | 경쟁이 질문한다는 주어-술어가 어색함 | 제품과 연구가 모델 바깥의 실행 조건을 다루기 시작했다는 식으로 구체화 |
| `연구자들은 하네스도 성능을 바꾸는 변수로 봅니다` | 보고서식 요약 제목 | 하네스 절차를 바꾸면 같은 모델에서도 결과가 달라진다는 쪽으로 구체화 |
| `Connector는 편의 기능이자 권한의 입구입니다` | `A이자 B` 구조가 정리문처럼 보임 | connector가 업무 데이터 접근과 권한 기록을 동시에 만든다는 장면 중심 제목 |
| `오픈소스는 하네스를 손으로 만져보는 실험장입니다` | 은유가 넓고 제목만으로 내용이 덜 보임 | 터미널, 세션 재개, 스킬 관리 같은 실제 요소를 드러냄 |
| `AI 코딩의 병목은 이제 변경 관리에 남습니다` | `이제`, `병목`, `남습니다`가 AI식 기술동향 제목처럼 보임 | 생성 이후 테스트, 병합, 되돌리기가 팀 작업의 조건이 된다는 식으로 수정 |
| `에이전트 구성은 수보다 역할이 먼저입니다` | `A보다 B` 대비 구조 | 절차형 작업과 병렬 작업의 조건 차이로 설명 |
| `이제 모델명 대신 하네스를 물어볼 차례입니다` | 마무리 슬로건 | 실제 도입 질문을 회수하는 제목으로 수정 |

## 우선 수정할 표현군

| 표현군 | 현재 문제 | 수정 방향 |
|---|---|---|
| `붙여`, `붙잡아주는`, `곁에 둬야` | 관계를 설명하는 듯하지만 실제 운영 구조가 흐려짐 | 권한 부여, 기록, 테스트, 승인, 되돌리기처럼 구체 동작을 쓴다 |
| `이어집니다`, `넓어집니다`, `옮겨갑니다` | 추상 주어가 문장을 끌고 감 | 제품/연구/팀이 무엇을 새로 요구하는지 직접 쓴다 |
| `출발점입니다` | 7회 반복. 글의 결론을 한 단어에 기대게 됨 | 문맥별로 `첫 조건`, `초기 선택`, `검토 기준` 등으로 나누거나 삭제 |
| `가깝습니다` | 비유와 설명을 쉽게 닫는 만능 표현 | 비유 뒤에 실제 구성요소를 직접 제시 |
| `좋은 X는 ...` | 평가가 근거보다 앞섬 | 관찰된 조건을 먼저 쓰고 평가를 뒤로 보냄 |
| `질문`, `함께`, `구조`, `장치` 반복 | 글 전체 리듬이 비슷해짐 | 섹션별 주어와 동사를 다시 세움 |

## 다음 재작성 순서 제안

1. 소제목을 먼저 바꾼다.
2. 도입부와 참고자료 표 사이에 업무 장면을 한 단락 더 넣거나 표를 뒤로 옮긴다.
3. `micro_cadence` 항목이 잡힌 문장을 우선 고친다.
4. 각 섹션의 시작 방식을 서로 다르게 만든다.
5. 마무리 섹션을 bullet checklist가 아니라 사례 회수형 문단으로 다시 쓴다.

## 다음 vibe 퇴고 후보

자동 감사는 통과했지만, 사람과 함께 볼 만한 문장은 남아 있다.

| 후보 | 다시 볼 이유 | 제안 방향 |
|---|---|---|
| `이번 리뷰에서는 그 안팎의 논문... 살펴보겠습니다.` | 친근한 진행 문장으로 쓸 수 있지만, 리뷰 메타 문장으로 보일 수도 있다. | `이 자료들을 다시 확인해보면...`처럼 자료의 움직임에서 바로 본문으로 연결할 수 있다. |
| `최근 자료는 모델 바깥의 실행 조건을 더 자주 다룹니다` | 의미는 분명하지만 `자료는 ... 다룹니다`가 약간 보고서식이다. | `논문과 제품 발표에서 실행 조건이 더 앞에 놓이기 시작했습니다` 같은 방향을 검토한다. |
| `하네스는 모델 주변의 운영 조건을 정합니다` | 간명하지만 제목의 온도가 조금 낮다. | 독자가 바로 잡을 수 있는 업무 장면을 제목에 더 넣을 수 있다. |
| `코드를 만든 뒤에는 테스트와 병합이 남습니다` | 짧고 이해는 쉽지만 `남습니다`가 다시 보고서식으로 들릴 여지가 있다. | `코드가 빨리 만들어질수록 테스트와 병합이 더 중요해집니다`처럼 인과를 드러낼 수 있다. |
| `도입 판단은 모델 선택 뒤의 운영 조건에서 갈립니다` | 메시지는 좋지만 제목이 다소 추상적이다. | `모델을 고른 뒤에는 권한, 기억, 병합을 물어야 합니다`처럼 문장형 제목을 검토한다. |
